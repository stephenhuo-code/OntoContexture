# 半导体与存储企业的业务组织框架：“研产供销服”的对应体系

> 调研日期：2026-11-17 · 访问日期同前 · 用途：回答“美光这类非传统制造企业有没有类似研产供销服的体系化组织逻辑”；第 4、5 节的框架组合与对织境的意义为分析推断

## 1. 一页结论

1. **没有一个公开的、专门面向半导体企业的“业务域地图”。** 能找到的是几套各管一段的框架，可以拼起来用：
   - SIA 与 BCG 的半导体价值链七类活动（行业结构）；
   - 美光年报（10-K）的组织方式（企业实际怎么分）；
   - 美光投资者材料里的技术生命周期和客户协同链（时间维度）；
   - APQC 流程分类框架（跨行业流程目录）；
   - ISA-95（工厂内从设备到 ERP 的分层）；
   - ASCM 的 SCOR 供应链模型（部分核实）。
2. **与传统制造业相比，半导体与存储企业的组织逻辑有四点不同**：
   - **“研”分成两条线**：工艺技术研发（技术节点）和产品研发（芯片设计、固件、验证），各有自己的生命周期；
   - **“研”和“产”之间有一个独立阶段**：良率爬坡；
   - **“销”提前进入“研”**：与大客户共同定义、共同设计（如定制 HBM）；
   - **“服”有一半在售前**：客户认证、联合验证，而不只是售后。
3. **美光自己的组织是“双轴”**：产品技术轴（DRAM、HBM、NAND、SSD 等）× 市场业务单元轴（CMBU、CDBU、MCBU、AEBU）。传统的“研产供销服”是单轴的。
4. **建议的组织逻辑（分析推断）**：横向用“研产供销服”的五域（便于和传统制造业客户沟通），但按半导体行业的实际拆成子域；纵向叠加技术与产品生命周期；经营上叠加“产品技术 × 市场业务单元”两条轴。

## 2. 可以依据的框架

### 2.1 半导体价值链（SIA × BCG，2021）（A）

SIA 与 BCG 的报告《Strengthening the Global Semiconductor Supply Chain in an Uncertain Era》（2021-04）把半导体价值链分为七类活动：

| 类别 | 活动 |
| --- | --- |
| 核心环节 | ① 前竞争性研究（Pre-competitive research） ② 设计（Design） ③ 前道：晶圆制造（Front End: wafer fabrication） ④ 后道：组装、封装与测试（Back End: assembly, packaging & testing） |
| 支撑环节 | ⑤ EDA 与核心 IP ⑥ 设备与工具 ⑦ 材料 |

报告列出四种商业模式：

| 模式 | 定义（报告原意） |
| --- | --- |
| IDM（垂直整合制造商） | 设计、制造、组装封装测试都在内部完成；部分为“轻晶圆厂”（fab-lite）；**“IDM 模式在存储和 DAO（分立、模拟、光电等）企业中更常见”**；2019 年 IDM 约占全行业 70% 的销售额 |
| Fabless（无晶圆厂设计公司） | 只做设计 |
| Foundry（晶圆代工） | 为他人制造晶圆 |
| OSAT（外包封测） | 为 IDM 和 Fabless 提供组装、封装、测试服务 |

### 2.2 美光的实际组织（10-K，FY2026，2026-10-09 提交）（A）

**年报第 1 项（Business）的章节顺序**：概述；产品、市场与销售（产品技术；按业务单元和市场划分的产品）；营销与客户；竞争状况；制造；资源（供应链、材料与第三方服务商；专利与许可）；研究与开发；人力资本；政府监管；环境健康安全；贸易监管；高管信息。

**两条轴**：

| 轴 | 内容 |
| --- | --- |
| 市场业务单元（报告分部，FY2025 第四季度起采用，FY2026 沿用） | **CMBU 云存储器**：面向大型超大规模云客户的存储器方案，以及面向所有数据中心客户的 HBM<br>**CDBU 核心数据中心**：面向中型云、企业和 OEM 数据中心客户的存储器方案，以及面向所有数据中心客户的存储（SSD）方案<br>**MCBU 移动与客户端**：面向移动和客户端市场的存储器与存储方案<br>**AEBU 汽车与嵌入式**：面向汽车、工业和消费市场的存储器与存储方案 |
| 产品技术 | DRAM、HBM、NAND、固态硬盘（SSD）、Managed NAND、多芯片封装（MCP）、NOR |

**各域在年报中的描述**：

| 域 | 年报原意 |
| --- | --- |
| 研发 | 同时覆盖工艺技术（如 1δ DRAM 节点引入 EUV）和产品设计（HBM、DDR、LPDDR、大容量 DRAM 模组等）；研发中心位于博伊西、圣何塞、印度、日本、中国台湾、新加坡 |
| 制造 | 制造过程“包括晶圆制造、晶圆后处理、组装和测试等大量精密步骤”；“许多产品在内部组装，部分外包组装”；“在制造过程的多个阶段测试产品”；部分步骤使用分包商；300mm 晶圆，全天候生产 |
| 供应链 | 依赖满足严格标准的材料；通常有多个来源；许多合同没有长期产能或价格承诺 |
| 销售与客户 | 直销团队加分销商、零售商和独立代表；前十大客户约占一半收入 |
| 质保与退货 | **年报第 1 项没有单独章节**，只在风险因素中出现：产品不符合规格、有缺陷或与最终用途不兼容的风险；系统级产品的延长质保可能增加质保成本 |

### 2.3 美光投资者材料里的两条时间线（2026-10-21）（A）

| 页 | 内容 | 含义 |
| --- | --- | --- |
| 第 16 页 DRAM 路线图 | 节点阶段：Pathfinding（路径探索）→ Early development（早期开发）→ Development（开发）→ Yield ramp（良率爬坡）→ In high-volume manufacturing（大规模量产） | **技术节点生命周期**；良率爬坡是研发与量产之间的独立阶段 |
| 第 27 页 | “AI makes Micron 2x faster: invention to volume production”，衡量指标为“到流片”“到可向客户发布” | **产品生命周期**：从发明到量产 |
| 第 31 页 | 与客户和生态伙伴协同：Co-imagine（共同构想）→ Co-design（共同设计）→ Co-develop（共同开发）→ Co-validate（共同验证）→ Deliver at scale（规模交付）；包括“把 AI 负载转化为新的存储器架构”“与多家云服务商开发定制产品”“与 EDA 厂商利用 AI 设计流程”“与晶圆代工伙伴协同设计”“美光、客户和伙伴共同认证方案” | **客户协同链**：销售与服务在研发阶段就介入 |
| 第 29 页 | 长周期研发投入：Micron Ventures（3–10 年）、Albany NanoTech 与 NY CREATES（5–10 年，高 NA EUV 与光刻）、Micron Research Labs（10 年以上） | 研发再分为前瞻研究与产品化开发 |

### 2.4 通用流程与制造框架

| 框架 | 内容 | 核实情况 |
| --- | --- | --- |
| **APQC 流程分类框架（PCF）** | 13 个跨行业类别：1 制定愿景与战略；2 开发与管理产品和服务；3 营销与销售；4 交付实物产品；5 交付服务；6 管理客户服务；7 人力资本；8 信息技术；9 财务资源；10 获取、建设与管理资产；11 企业风险、合规、补救与韧性；12 外部关系；13 业务能力。层级为类别、流程组、流程、活动、任务。行业版沿用核心结构和编号 | A（APQC 官方说明，2018）。**没有找到半导体专用版本**；最接近的“消费电子”版只见检索结果（C） |

| **SEMI 设备与数据标准** | E90 衬底追踪、E142 衬底映射、E30 GEM 等 | C（官网 403 或限流，只见检索摘要） |

## 4. 建议的组织逻辑：半导体版“研产供销服”（分析推断）

## 5. 对织境的意义（分析推断）

1. **可作为行业本体的顶层划分依据**：织境用 OpenMetadata 承载本体与元数据。面向半导体与存储客户时，可以考虑按第 4 节的五域和子域组织业务域；具体如何映射到 OpenMetadata 的域、术语表等对象，需要在后续 spec 中按项目约定确定，本文不做设计。
2. **前几份调研的场景都能归位**：

| 场景 | 所在域 |
| --- | --- |
| 美光研发测试 Agent | 研：芯片设计、固件开发、设计验证 |
| 良率根因分析、AI-ADC、设备监测 | 产：良率与质量管理、设备与厂务 |
| BOM 追溯、代工与外包封测数据接入 | 供 |
| 客户认证问答 | 服：客户认证 |
| RMA 与 8D | 服：质保与退货、失效分析 |

3. **跨域追溯是上下文层的价值所在**：例如一次客户退货，要从“服”（退货）追到“产”（批次、测试记录）、“供”（NAND 来源批次）、“研”（固件版本），这条链跨越全部五个域。

## 6. 局限与待核实

- **没有半导体专用的流程框架**：APQC 没有找到半导体版 PCF；也没有找到 SEMI、SAP、西门子、应用材料公开的半导体业务能力地图。
- **部分框架未完整核实**：SCOR 数字标准的七个流程只经行业媒体和检索摘要确认；ISA-95 第 3 部分的运营类别、SEMI E 系列标准、STDF 格式均未打开原文。
- **第 4 节的子域是分析推断**：用于讨论，不能直接作为产品概念；按 AGENTS.md 要求，进入 spec 前需以客户实际组织与系统为依据核对。
