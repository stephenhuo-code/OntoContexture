# ADR-0005 统一取数网关与工具型数据源

- 状态：已接受
- 日期：2026-10-04
- 决策人：@stephenhuo-code
- 影响特性：005、006、007、015、017、018、020、022、024
- 相关宪法条款：II（契约优先、独立服务）、IV（授权求值、审计、只读）、V（可观测性）
- 相关 ADR：ADR-0002（执行与沙箱）、ADR-0004（本体与实例的存储分层）

## 背景

按 ADR-0004，本体定义与元数据存于 OpenMetadata，全部对象实例存于 Doris 本体实例库，客户的分析
数据仍在客户数仓。内部 Agent、Notebook、指标模型、追溯与探索服务都需要取数，必须有统一的授权、
限流与审计入口。

此外，部分数据源本身以 MCP 服务、CLI 或 HTTP API 的形式提供（如 MES 自带的 MCP 服务、金蝶 /
用友的 MCP、DataWorks MCP、数据库厂商的 CLI），并登记为数据资产。它们是“工具”而不是“表”，
无法用 SQL 的方式做授权与执行。

## 决策

### 1. 006 定名为“统一取数网关”

统一取数网关是所有**实例数据、分析数据与运行态数据**的必经入口。它不存储数据，不是数仓；本体
定义、元数据与血缘通过 OpenMetadata API 获取，不经过网关。

```
                          调用方
   内部 Agent / Notebook / 指标模型 / 追溯服务(015) / 探索(018)
                            │
          ┌─────────────────┴──────────────────┐
          │ 查定义、元数据、血缘                 │ 查实例数据、分析数据、运行态数据
          ▼                                     ▼
   OpenMetadata API                    006 统一取数网关
   （本体定义、表字段、血缘、            验身份 → 授权 → 只读、限流 → 执行 → 审计 / 轨迹
    数据源工具的登记信息）                      │
                          ┌──────────────────┼─────────────────────────┐
                          ▼                  ▼                         ▼
                   【SQL 后端】         【SQL 后端】             【工具型数据源】（二期）
                  Doris 本体实例库       客户数仓            以 MCP / CLI / API 登记的数据源
               （物化的对象实例）     （DWD / DWS）
                                    二期：IoTDB 时序、Trino 联邦
```

### 2. 两层查询分工

| 层 | 提供者 | 提问方式 | 主要使用者 |
| --- | --- | --- | --- |
| 本体查询 | 015 追溯与图谱服务（经 017 以 MCP 工具对外） | 按对象与关系提问，如“NCR-0815 的追溯链”“设备关联的检验记录” | Agent 的大部分场景、对象详情页、追溯图 |
| SQL 查询 | 006 统一取数网关 | 直接提交 SQL，查本体实例库或客户数仓 | 按口径取数（020）、Notebook（022）、沙箱数据管线（007）、临时分析 |

- 015 把本体查询翻译成 SQL 后，同样交给 006 执行；018 的查询也经 006。授权、限流与审计只在
  006 一处落实（宪法 IV）。
- 006 只负责“能不能查、查多少、记下来”，不理解业务含义；015 负责“怎么查”，不直接访问数据库。

### 3. Phase 1：SQL 后端

- 后端：Doris 本体实例库、客户数仓。
- 授权：
  - 本体实例库的表结构由本体生成（ADR-0004），表与列可直接对应到对象类型与属性；005 打在对象
    类型与属性上的分级标签据此实现**列级**授权。
  - 客户数仓的表按 OM 元数据上的分类标签授权（005）。
  - 求值规则为“人的权限 ∩ Agent 授权 ∩ 数据级别”，限定在令牌所属租户内，默认拒绝。
- 只读：只允许 SELECT；拒绝 DELETE、DROP、UPDATE 等写操作。
- 资源保护：超时、扫描量与返回行数上限；Doris 按租户与 Agent 划分 workload group。
- 临时 schema：为数据管线的中间结果按运行分配，设配额，到期自动清理；正式表永远只读。
- 结果：附数据来源与血缘；由指标生成的查询附口径引用（020）。
- 审计与轨迹：每次执行写入审计（005），并带 ADR-0001 规定的关联属性写入轨迹。
- **后端抽象**：执行层以统一的后端接口实现（提交请求 → 授权 → 执行 → 结果与审计），SQL 后端是
  其第一种实现，为二期的工具型数据源、IoTDB 与 Trino 预留，不改变调用方接口。

### 4. 二期：工具型数据源

Phase 1 不接入工具型数据源。二期按以下设计实现：

- **登记为数据资产**（OM）：访问地址与传输方式（MCP / CLI / HTTP API）、凭证引用（凭证存 KMS）、
  工具清单及每个工具的读写属性、输出字段到对象类型与属性的映射、数据级别、负责人。OM 的 API
  Service / API Endpoint 实体或 OM 2.0 的 AI 资产注册表能否承载，届时确认。
- **网关代理**：Agent 只看到织境 MCP 工具（017），由网关转发到登记的数据源工具，MUST NOT 直连
  数据源。
- **授权**：按“工具 + 参数约束”求值；返回结果按输出字段映射的分级标签逐字段过滤。
- **只读**：只放行登记为只读的工具，参考 MCP 工具的只读标注；写类工具纳入二期写回的审批流程。
- **凭证**：数据源支持 OAuth（MCP 授权规范）时，以委托令牌换取代表该用户的下游令牌；否则使用登记
  的服务账号。凭证 MUST NOT 暴露给 Agent。
- **执行**：MCP 由网关作为 MCP 客户端调用；CLI 在 007 沙箱中执行，只允许登记的命令。
- **物化与实时合成**：012 物化到 Doris 的数据用于追溯与统计；部分属性（如工单当前状态、设备实时
  告警）通过工具实时获取。015 查询对象时把两者合成为同一个对象，对应产品规划“运行态数据经网关
  实时获取”。
- 限流、审计、轨迹与 SQL 后端一致。

## 影响

正面：
- 取数的授权、限流与审计只有一个落实点；调用方不感知数据来自 Doris、客户数仓还是工具型数据源。
- 本体生成的表结构让列级授权直接按对象属性表达。
- 后端抽象使二期接入工具型数据源、时序库与联邦查询不影响调用方。

负面与代价：
- 网关是所有取数的关键路径，需要高可用与性能压测；P95 延迟目标在 006 的 plan 中确定。
- 015 的本体查询多一跳经过网关，需要控制额外延迟。
- 工具型数据源推迟到二期，若 POC 客户的关键数据只以 MCP 形式提供，需要提前评估。
