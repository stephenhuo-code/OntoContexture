# ADR-0007 多租户隔离

- 状态：已接受
- 日期：2026-10-04
- 决策人：@stephenhuo-code
- 影响特性：001、002、005、006、009、011、012、015、016、017
- 相关宪法条款：IV（租户限定、默认拒绝）、部署约束（测试环境共享实例支持多客户）
- 相关 ADR：ADR-0001、ADR-0004、ADR-0005

## 背景

阿里云测试环境以一套共享实例支持多个客户（宪法“部署约束”），客户生产环境按单租户运行，两者使用
同一套代码。OpenMetadata、OpenSearch、Fuseki 都不原生支持多租户。

## 决策

### 1. 租户身份

- Keycloak **单 realm + Organizations**：每个租户一个 organization；客户 IdP 按 organization 接入。
- 令牌携带租户声明 `tenant_id`（由 organization 映射）；租户标识只取自签名令牌（宪法 IV）。
- 单租户部署视为只有一个 organization，规则不变。

### 2. 各存储的隔离方式

| 存储 / 组件 | 隔离方式 | 强制点 |
| --- | --- | --- |
| PostgreSQL（各服务库） | 共享表 + `tenant_id` 列 + 行级安全（RLS）；会话变量由公共库按请求上下文设置 | 数据库 RLS + 公共库 |
| Doris 本体实例库 | 每租户一个 database（ADR-0004），配合行策略 | `gateway` 按令牌租户路由 |
| Doris 审计库 | 共享表 + `tenant_id` 列；查询经 `iam` 按租户过滤 | `iam` |
| OpenMetadata | 每租户一个 Domain，租户相关资产（源系统元数据、映射、租户本体分支）归属该 Domain；标准本体与领域包为平台共享；织境服务以服务账号访问 OM 并按 Domain 过滤；OM 界面不对客户开放（ADR-0003） | 织境服务层 |
| Fuseki（RDF） | 平台共享本体一个命名图，每租户的本体分支与元数据各一个命名图 | `ontology` 服务 |
| OpenSearch | OM 自身索引按 Domain 过滤；织境的本体实例搜索索引每租户一个 | `graph` 服务 |
| Langfuse | 每租户一个 project（ADR-0001） | `trace` 服务 |
| 对象存储 | 每租户一个前缀，访问凭证按前缀授权 | 公共库 + 存储策略 |
| Airflow | DAG 运行以租户为参数；按租户的资源池与连接凭证 | 管线规范 |
| Omnigent | 会话、Agent、沙箱按租户隔离（ADR-0002 改造项） | Omnigent 补丁 + 扩展 |

### 3. 测试要求

- 每个对外接口 MUST 有跨租户隔离测试（宪法“部署约束”）；公共库提供测试夹具。
- 端到端骨架包含两个测试租户的互访测试（001）。

## 理由

- 单 realm 使所有服务只需信任一个签发者，配置与验签最简单；Organizations 支持按租户接入客户 IdP。
- 各存储按其能力选择最强且可行的隔离方式；OM 无原生多租户，只能在服务层强制，并以“OM 界面不对客户
  开放”为前提。

## 考虑过的其他方案

| 方案 | 结论 |
| --- | --- |
| 每租户一个 Keycloak realm | 不采用：签发者随租户变化，服务需动态信任多签发者 |
| 每租户一套 OpenMetadata | 否决：测试环境禁止按客户部署多套实例 |
| PostgreSQL 每租户一个 schema / database | 不采用：Phase 1 租户少，RLS 足够且迁移简单；二期视需要调整 |

## 影响

- 所有访问 OM 的织境服务必须按 Domain 过滤，否则会跨租户泄露；需在公共库提供 OM 访问封装与测试。
- OM 中的标准本体与领域包为平台共享，租户只在自己的分支中扩展。

## 修订（2026-10-07，见 ADR-0012）

- Phase 1 经 OM 交付的上下文（AI 上下文、上下文中心、MCP）不做织境层面的租户隔离（宪法 IV Phase 1 例外）；测试环境可选用 OM 的域访问策略做软隔离。
- 取数入口按令牌租户路由到该租户的 Doris database（2026-10-08 起由 AI 网关路由到该租户的 MCP Toolbox 实例，ADR-0013）。
