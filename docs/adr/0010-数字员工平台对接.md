# ADR-0010 外部 Agent 平台对接

- 状态：已接受
- 日期：2026-10-04（2026-10-08 改为已接受，明确不绑定外部框架与对外接入契约）
- 决策人：@stephenhuo-code
- 影响特性：005、009、010、011、013、021
- 相关宪法条款：IV（委托令牌、只信任签名令牌、外部平台的身份口径）
- 相关 ADR：ADR-0001（轨迹）、ADR-0002（Omnigent）、ADR-0013（数据访问与 AI 网关）

## 背景

织境是“供企业自有数字员工平台调用的上下文层”。客户很可能自己构建 AI 工作与 Agent 系统（如 Paperclip、Dify、
OpenClaw 或自研平台），这些系统大多以整个平台作为一个 OAuth 客户端访问外部 MCP，不会为每个 Agent 做令牌交换，
也不一定回传完整轨迹。织境需要一套这些系统都能接入的标准方式。

## 决策

### 1. 不绑定外部 Agent 框架

织境只承诺标准接口。Omnigent 仅作为织境自有 Agent 的运行时（ADR-0002）与对外的参考客户端，不要求客户使用。

### 2. 对外接入契约

| 项 | 要求 |
| --- | --- |
| 协议 | 标准 MCP（Streamable HTTP），统一入口为 AI 网关（ADR-0013） |
| 授权 | 遵循 MCP 授权规范：Keycloak 作授权服务器，AI 网关提供受保护资源元数据，令牌受众绑定 AI 网关；客户端可预先登记，也可动态登记（Keycloak 的客户端元数据文档登记为实验特性，按需开启） |
| 身份 | **A 档**：每个 Agent 一个客户端并做标准令牌交换，`azp` 精确到具体 Agent（织境自有 Agent 与参考客户端）<br>**B 档**：外部平台作为一个 OAuth 客户端代表人访问，`sub` 为人、`azp` 为平台；平台内部的具体 Agent 由平台在请求中声明，记录时注明未验证（宪法 IV）<br>**C 档**：无人值守任务以服务账号运行，登记负责人 |
| 上下文 | 经 MCP 取 OKF v0.2 上下文（OM 内置 MCP，经 AI 网关）；另提供 Skills（agentskills.io 格式）与 OKF 文件，供不支持 MCP 的平台导入 |
| 取数 | 经 MCP 调用 MCP Toolbox 等数据库 MCP 服务（ADR-0013） |
| 轨迹 | **织境侧必有**：AI 网关记录每次调用（人、平台或 Agent、工具、查询摘要），汇入 Langfuse<br>**平台侧可选**：以 OTLP 或 Webhook 回传完整轨迹（ADR-0001） |

B 档下，“按 NCR / 人 / Agent 查询轨迹”中的 Agent 精确到平台；平台声明的具体 Agent 仅作参考。

### 3. 参考客户端与兼容性验证

- 参考客户端：Omnigent，按 A 档接入，用于验证完整的身份与轨迹契约。
- 兼容性测试矩阵：对 2–3 个主流外部平台按 B 档做接入测试（候选：Paperclip，以及支持远程 MCP 连接器的平台），在
  011 问数 Skill 与 021 8D Skill 中验收。
- 005 提供外部平台接入指南：客户端登记方式、令牌获取、可用工具、轨迹回传方式。

### 4. 飞书

P1 / P2 的主要工作平台为飞书：8D 草稿推送与修改回收经飞书（013、021）。POC 客户实际使用的飞书 Agent 产品形态
在 013 的 plan 阶段确认，并按本契约的 B 档接入。

## 理由

- 客户自建 Agent 系统是常态，绑定任一框架都会挡住客户；标准 MCP 加 OAuth 是各平台的公约数。
- 身份分档后，织境自有部分仍满足“每个 Agent 有签名身份”，外部平台也能按其能力接入，宪法 IV 以平台为 Agent 身份兜底。
- 轨迹在 AI 网关一侧必定留存，不依赖外部平台是否回传。

## 考虑过的其他方案

| 方案 | 结论 |
| --- | --- |
| 为特定平台提供专用接口 | 不采用：违背“开放、中立”的产品定位 |
| 要求所有外部平台做到 A 档 | 不采用：多数平台做不到，会挡住客户 |
| 把参考客户端换成 Paperclip | 暂不采用：其以平台身份取令牌、未见 OIDC 单点登录与 Agent 轨迹输出，作为兼容性测试对象更合适 |
| 只支持 Omnigent | 不采用：参考实现不能代表客户平台 |
