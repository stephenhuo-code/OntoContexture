# ADR-0010 数字员工平台对接

- 状态：提议（待确认 POC 客户的实际平台）
- 日期：2026-10-04
- 决策人：@stephenhuo-code
- 影响特性：009、016、017、019、024
- 相关宪法条款：IV（委托令牌、只信任签名令牌）
- 相关 ADR：ADR-0001（轨迹）、ADR-0002（Omnigent）

## 背景

织境是“供企业自有数字员工平台调用的上下文层”，P1 / P2 的消费方是谁，决定参考 Skill 的形态与轨迹
回传方式。产品规划与 POC 路线图均以飞书为主要工作平台。

## 决策（提议）

1. **对外只承诺标准接口，保持中立**：
   - MCP（Streamable HTTP），统一经 AI 网关接入：上下文为 OM 内置 MCP（ADR-0012），取数为 MCP Toolbox 等数据库 MCP 服务（ADR-0013）；授权遵循 MCP 授权规范（OAuth），调用必须携带经 Keycloak 标准令牌交换得到、能标识人（`sub`）与 Agent（`azp`）的委托令牌；
   - OM 资产 AI 上下文（OKF v0.2 知识包，ADR-0012）。
2. **P1 / P2 的主要对接平台为飞书**：8D 草稿推送与修改回流经飞书（010、019）。
3. **轨迹回传**：支持 OTLP 与 Webhook 两种方式写入 OTel Collector（ADR-0001）。
4. **参考 Agent**：以 Omnigent 作为客户侧参考客户端（ADR-0002），用于验证身份与权限契约；另选一个客户
   实际使用的平台做兼容性测试。

## 待确认

- POC 客户实际使用的飞书 Agent 产品形态。
- 该平台能否在调用外部 MCP 时携带当前用户的令牌；若不能，需要在织境侧提供令牌代换方案并经安全评审。

## 考虑过的其他方案

| 方案 | 结论 |
| --- | --- |
| 为特定平台提供专用接口 | 不采用：违背“开放、中立”的产品定位 |
| 只支持 Omnigent | 不采用：参考实现不能代表客户平台 |
