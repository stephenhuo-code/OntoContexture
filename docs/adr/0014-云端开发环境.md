# ADR-0014 云端开发环境：在 DOKS 上部署一套织境并兼作开发环境

- 状态：草案（030 实施中，收尾时定稿）
- 日期：2026-11-11
- 决策人：@stephenhuo-code
- 影响特性：030（029 阿里云测试环境可复用其脚本与参数化方式）
- 相关宪法条款：部署约束（自有测试环境）、I（测试与覆盖率）、III（开源许可）、IV（凭证）

## 背景

负责人的开发机 devbox-0 运行在 DigitalOcean Kubernetes（DOKS）中：约 1.5 核、2 GB 内存，没有 Docker，无法运行本地 kind 部署。
需要一套可通过公网域名访问的织境环境，同时作为日常开发环境：改代码不经 git 即可生效，构建与测试在集群内执行。
需求与决定过程见 `specs/030-doks-deploy/`（spec、research R1–R19、R17a）。

## 决定

（实施完成后按实测结论定稿，草案要点如下）

1. 复用现有 helmfile 与组件 Chart，新增 `cloud` 环境；本地 `local` / `lite` 渲染结果不变。
2. 入口：Envoy Gateway + 云负载均衡器 + cert-manager（Let's Encrypt HTTP-01）；不修改 DOKS 托管的 Gateway API CRD。
3. 身份：集群内自带 Keycloak。
4. 镜像：bff / web 在集群内用 BuildKit 构建；OpenMetadata 相关镜像只由手动触发的 GitHub Actions 构建；仓库为 DOCR。
5. 开发模式：DevSpace 替换 bff / web 的 Pod 并同步源码，退出时恢复稳定版本。
6. 测试：一次性工具箱 Pod（带 docker:dind 边车）运行现有测试；bash 脚本覆盖率用 kcov 统计。
7. 启停：按依赖顺序缩容 / 恢复工作负载，CNPG 休眠，弹性池由集群自动扩缩释放。
8. 可移植性：云厂商专用值（节点池标签、负载均衡器注解、存储类、镜像仓库）全部来自配置。

## 许可例外

kcov 为 GPL-2.0，只用于 CI 工具箱与 CI 运行器统计 bash 覆盖率，不进入任何交付物或运行时镜像；登记于 `tools/license-allowlist.yaml`。
