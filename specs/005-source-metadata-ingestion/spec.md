# Feature Specification: 源系统元数据采集（Source Metadata Ingestion）

**Feature Branch**: `005-source-metadata-ingestion`

**Created**: 2026-11-05

**Status**: Draft

**Input**: User description: "根据已确认 HTML 原型（`specs/005-source-metadata-ingestion/prototype/index.html`）与 OpenMetadata 2.0.3 数据源管理模块原生能力编写源系统元数据采集规格：真实接入 MES、QMS、ERP 与数仓的表、字段及数据库视图血缘，由独立 Airflow 调度；严格按原型的布局与交互实现数据源列表、四步接入配置向导、数据源详情（概览、已采集元数据、采集配置、采集任务与运行详情）以及四层元数据目录（服务 → 数据库 → Schema → 表与字段）和治理属性维护。国产数据库接入适配及评估不纳入本期；帆软 SQL 解析暂缓，不复制业务数据。"

## 界面与交互基线（对齐 HTML 原型与 OpenMetadata 数据源管理）

本特性严格以已确认的高保真原型 `specs/005-source-metadata-ingestion/prototype/index.html` 为界面与交互设计基准，并对齐 OpenMetadata 2.0.3 原生数据源管理模型（`DatabaseService`、`IngestionPipeline`、`TestConnection`、`Database`、`DatabaseSchema`、`Table`、`Column`）：

1. **左轨与二级侧栏导航**：
   - 在织境 Web 外壳的“资产（数据资产）”工作空间下，左侧二级导航包含“数据接入 → 数据源”入口（路由 `/sources`），以及下方可展开/收起的**四层数据源目录树**（`数据源服务 → 数据库 → Schema → 数据表`）。
   - 目录树服务节点右侧显示已采集表数量（未采集时显示“未采集”）；窄屏/移动端（≤ 850px）顶栏提供“目录”按钮抽屉式展开侧栏目录树。
2. **数据源列表页（`/sources`）**：
   - **页头**：`DATA INGESTION` 眉标、“数据源”主标题、副标题，以及右侧主按钮“+ 添加数据源”（点击打开四步配置弹窗向导，不跳转独立简陋表单页）。
   - **顶部 4 张汇总指标卡（Stats）**：
     1. **已配置数据源**：已配置数 / 总数据源数，及覆盖说明；
     2. **已采集表**：已采集数据表总数（张）；
     3. **字段元数据**：已采集字段总数（个，含字段类型与业务注释）；
     4. **需要关注**：存在采集失败或部分成功的数据源数量（项），无异常时显示“最近采集均已完成”。
   - **工具栏与数据源表格**：
     - 搜索框（按名称、服务标识、连接器或数据库即时过滤）、状态下拉筛选（`全部状态` / `采集成功` / `需要关注` / `待配置` / `调度已暂停`）、数据源计数与“重置筛选”按钮。
     - 表格列：`数据源 / 连接器`（带配色缩写图标徽章、显示名称链接、`<连接器> / <服务标识>` 副标题）、`最近采集`（状态徽章 + 采集结果/血缘摘要）、`元数据`（表数 + 字段数，待配置显示 `— / 尚未采集`）、`调度`（计划时间或“手动触发”或“已暂停”徽章 + 时区 `Asia/Shanghai`）、`更新时间`（最近运行时间 + 耗时）、`操作`（`查看详情` 或 `继续配置`）。
     - 面板底栏：展示“采集结果统一写入 OpenMetadata”与“独立 Airflow 调度”。
   - **底部双栏信息卡**：
     - 左侧提醒卡（`notice-card`）：存在需关注的数据源时高亮提示原因并提供快捷跳转链接；全部正常时展示正常状态说明。
     - 右侧架构条（`pipeline-strip`）：展示 `源系统 → OpenMetadata Ingestion → 元数据目录` 采集边界说明（只采集元数据，业务数据保留在源系统）。
3. **四步数据源接入与配置向导（Modal 弹窗）**：
   - 步骤条：`1 选择连接器` → `2 连接验证` → `3 采集范围` → `4 调度与确认`。
   - **步骤 1（选择连接器）**：填写`显示名称 *`、`服务标识 *`（`2–50` 位小写字母、数字或连字符，以字母开头；已有数据源不可修改服务标识与连接器类型），选择数据库连接器卡片（`MySQL`、`PostgreSQL`、`Oracle`、`SQL Server`、`Doris`）。向导中不混入业务域等治理字段。
   - **步骤 2（连接验证）**：按所选连接器填写 OpenMetadata 原生连接参数，只暴露必填与常用项（`主机地址 *`、`端口 *`、只读`用户名 *`与`密码 *`、TLS 开关，以及按连接器区分的库字段：MySQL / Doris 为选填`数据库`（`databaseSchema`，留空即全部库，范围由步骤 3 过滤规则限定）；PostgreSQL / SQL Server 为必填`数据库 *`（`database`，`ingestAllDatabases=false`）；Oracle 为必填`Service Name *`（`oracleConnectionType.oracleServiceName`）；其他高级连接字段不暴露；密码由 OpenMetadata `SecretsManager` 加密存储并在查询响应中脱敏为 `*********`）。提供“测试连接”按钮，由 OpenMetadata 在采集执行环境中按该连接器的原生检查步骤（如 MySQL 的 `CheckAccess`、`GetSchemas`、`GetTables`、`GetViews`、`GetQueries`）逐项校验，弹窗内逐项展示步骤名称、必需/可选与通过、失败或未执行结果及失败原因；必需步骤全部通过方可进入下一步，`CheckAccess` 失败时后续步骤不执行；测试只读取元数据目录，不返回表清单，不读业务行；连接参数变更后须重新测试通过。
   - **步骤 3（采集范围）**：按 OpenMetadata 原生过滤规则提供`数据库`、`Schema`、`表`三级“包含 / 排除”输入（正则表达式，多个以逗号分隔，分别映射为 `databaseFilterPattern`、`schemaFilterPattern`、`tableFilterPattern` 的 `includes` / `excludes`；全部留空即采集全部，含后续新增对象），保存前校验正则合法性；提供“采集视图（视图元数据与视图定义）”开关（`includeViews`）与“创建视图血缘任务”开关（仅在采集视图时可选），并展示采集边界标签（`表与字段元数据`、`无数据采样`、`无数据剖析`、`不自动删除历史元数据`）。
   - **步骤 4（调度与确认）**：分别为元数据采集任务与（如创建）视图血缘任务选择调度方式（`每天定时采集` + `执行时间 · Asia/Shanghai`，或 `仅手动触发`），并提示视图血缘宜晚于元数据采集；展示“配置确认”汇总面板（数据源、目标数据库、采集范围、采集任务数量、调度执行、结果写入），点击“保存配置”同步完成 OpenMetadata `DatabaseService` 与各 `IngestionPipeline` 的保存及由 OpenMetadata 部署到 Airflow。
4. **数据源详情页（选中具体数据源服务）**：
   - 顶部提供 `← 返回数据源` 链接；页头展示数据源显示名称、`<服务标识> · <连接器> · <状态徽章>`，右侧提供“配置连接与范围”（或“继续配置”）按钮。
   - 包含 **4 个页签（Tabs）**：
     - **概览（`overview`）**：
       - **数据源属性卡片**：双列展示`显示名称`、`服务标识`、`连接器`、`描述`、`负责人`、`业务域`、`重要程度（Tier）`、`分类标签`、`业务术语`、`数据产品`，右上角提供“编辑属性”按钮打开属性编辑弹窗。
       - **异常提示条**（当最近采集为部分成功或失败时显示）：提示具体原因并提供“查看运行与处理建议 →”快捷跳转。
       - **3 张核心指标卡**：`已采集表`、`字段元数据`、`采集任务`（任务数量及类型）。
       - **底部双栏卡片**：左侧`连接信息`（数据库、连接地址、只读账号、采集边界）；右侧`调度与最近运行`（调度计划、时区、最近运行、执行状态、采集任务跳转链接）。
     - **已采集元数据（`metadata`）**：
       - 展示该数据源下的“数据库目录”表格（`数据库`名称链接与 FQN、`描述`、`Schema 数`）；尚未完成首次采集时展示空状态提示。
     - **采集配置（`scope`）**：
       - 左侧`采集范围`卡片（数据库、表选择/过滤范围、元数据内容、视图血缘开关状态，右上角提供“调整配置”按钮）；右侧`采集边界`卡片（4 项安全边界核对项）。
     - **采集任务（`tasks`）**：
       - **任务列表视图**：展示归属于该数据源服务的 OpenMetadata `IngestionPipeline` 列表（每个已配置数据源有一条元数据采集任务（`pipelineType=metadata`），以及可选的一条视图血缘任务（`pipelineType=lineage`）；任务名称按 OpenMetadata 规则为 `<服务标识>_<类型>_<8 位随机串>`（服务标识中的非字母数字字符替换为 `_`）；展示`任务名称`、`类型`、`调度计划`、`最近运行`、`操作：查看运行`）。
       - **任务运行视图**（点击任务名称或“查看运行”进入）：顶部提供 `← 返回采集任务`、任务标题与调度副标题，右侧提供“暂停调度 / 恢复调度”（弹窗确认）或“配置调度”按钮以及“立即运行”主按钮；下方运行记录面板支持按状态筛选（`全部状态` / `成功` / `部分成功` / `失败` / `采集中` / `排队中`）、手动刷新，表格展示`开始时间`、`状态`、`耗时`、`运行编号`（OpenMetadata `PipelineStatus.runId`，UUID）、`操作：查看运行`，不展示 OpenMetadata 未记录的触发方式；运行记录仅属于当前任务；底栏提供“调度详情”弹窗查看 Airflow DAG 关联信息（DAG 标识与任务名称一致）。
       - **运行详情弹窗（Modal）**：点击某次运行打开，展示数据源名称、任务类型与名称、运行编号、状态徽章、开始时间与耗时、OpenMetadata 原生步骤统计（`PipelineStatus.status` 中每个步骤——Source 步骤以连接器类型命名、Sink 步骤为 `OpenMetadata`——的记录、更新、警告、错误、过滤数）、失败对象及原因（`failures`，异常时）；仅对该任务最近一次运行展示脱敏日志（OpenMetadata 只提供最近一次运行日志），其他运行注明；异常运行提供“立即运行”以重新运行该任务（OpenMetadata 无单次运行重试操作）。
5. **下级元数据资产独立详情页（选中 `数据库` / `Schema` / `数据表`）**：
   - 从左侧四层目录树或“已采集元数据”逐层点击进入时，页面切换为**独立资产详情视图**：
     - 顶部提供 `← 返回所属数据源` 链接；页头眉标为 `METADATA CATALOG`，主标题为当前资产显示名称（未设时为物理名称），副标题为 `<数据库 | Schema | 数据表> · <完整 FQN>`。**不展示**所属数据源的采集状态徽章、“配置连接与范围”按钮或四个采集页签。
     - 展示可点击跳转的**资产层级面包屑**（`service › database › schema › table`，仅显示到当前选中层级）。
   - **数据库 / Schema 详情**：
     - 上方为**数据库属性 / Schema 属性卡片**（含“编辑属性”按钮，展示名称、显示名称、完整名称、描述、负责人、保留周期、业务域、重要程度、分类标签、业务术语、数据产品，并明确标注属性是“单独设置”还是“继承自 `<上级实体类型> · <上级 FQN>`”）。
     - 下方为**下级子项列表面板**（数据库页列出所含 Schema 及表数；Schema 页列出所含数据表及字段数）。
   - **数据表详情**：
     - 顶部提供同 Schema 下的“选择数据表”下拉切换框；
     - **数据表属性卡片**（含继承来源展示与“编辑属性”按钮）；
     - **结构信息卡片（只读）**：展示`表类型`（普通表 Regular / 视图 View 等）、`字段数`、`表约束`（如 `PRIMARY_KEY (...)`；Doris 键列按 OpenMetadata 原生 Doris 连接器记为主键约束，不区分 UNIQUE / DUPLICATE / AGGREGATE 键模型）及其他结构说明；
     - **字段元数据面板**：表格展示`字段名称`（等宽字体 + `PK` 徽章）、`数据类型`、`显示名称 / 描述`、`分类标签`、`业务术语`、`操作：编辑属性`（打开字段属性弹窗编辑显示名称、描述、分类标签、业务术语；字段不设独立的负责人、业务域、数据产品或保留周期）。

## Clarifications

### Session 2026-11-05

- （已于 2026-11-07 被替代，见下）Q: 向导步骤 3“表采集范围”在首次采集前如何既保持 HTML 原型的表勾选框列表交互，又对齐 OpenMetadata 的 `tableFilterPattern`？ → A: 在步骤 2“测试连接”通过时，由采集执行环境顺带通过只读元数据接口返回目标库的候选表名与表注释清单（不读业务行）；步骤 3 完全按原型展示“全部表（包含后续新增表）/ 仅采集选中的表”下拉切换与候选表复选框列表，保存时将所选表名自动映射为 OpenMetadata 原生 `tableFilterPattern.includes`。
- （已于 2026-11-07 被替代，见下）Q: “采集任务”与视图血缘的任务组织方式是单任务合并四阶段执行，还是拆分为两条独立采集任务？ → A: 对齐 HTML 原型单任务四阶段模型，每个数据源维护一条统一采集任务 `metadata_<服务标识>`（对应 OpenMetadata `IngestionPipeline`），勾选“采集视图定义，补充视图血缘”时在同一次运行中串联执行表/字段/视图定义提取与视图血缘解析写入，运行详情统一展示原型的四个阶段与状态（视图权限受限时记为 `partialSuccess` / 部分成功）。
- Q: 向导步骤 2 的数据库连接认证字段如何与 OpenMetadata 原生模型对齐？ → A: 直接采用 OpenMetadata 原生连接表单结构（`username` 用户名 + `password` 密码），由 OpenMetadata 原生 `SecretsManager`（Fernet / K8s Secret）加密存储并在所有查询响应与运行日志中自动脱敏（`*********`），不在 BFF 维护自定义“凭证引用”映射表。

### Session 2026-11-07

背景：首轮实现偏离 OpenMetadata 原生链路，已废弃并回到原型与规格；负责人决定“OpenMetadata 是什么样就尽量一致，第一期不加功能”，原型已按此调整（依据见 `prototype/openmetadata-alignment.md` 第 9 节）。

- Q: OpenMetadata 2.0.3 原生测试连接不返回表清单，首次采集前的采集范围如何设定？ → A: 与 OpenMetadata 一致：测试连接只展示该连接器原生检查步骤的结果；采集范围改为数据库 / Schema / 表三级“包含 / 排除”正则过滤规则（全部留空即全部），不提供候选表勾选。
- Q: OpenMetadata 原生把表 / 字段采集与视图血缘分为 metadata 与 lineage 两类管道，采集任务如何组织？ → A: 按 OpenMetadata 原生拆为两条任务：元数据采集任务（必有）与视图血缘任务（可选，需同时采集视图，`processViewLineage=true`、`processQueryLineage=false`）；各自调度、暂停 / 恢复、立即运行与运行记录；运行详情使用原生步骤统计而非自定义四阶段。
- Q: OpenMetadata 原生 Doris 连接器不识别 UNIQUE KEY，数据表详情如何展示 Doris 约束？ → A: 本期不做 UNIQUE KEY 识别；Doris 键列按原生连接器显示为 `PRIMARY_KEY` / `PK`，在 `acceptance.md` 中注明为已知限制。
- Q: 向导第 2 步的连接表单，要不要按 OpenMetadata 各连接器的原生字段来做，不再统一成一个必填的“数据库”？ → A: 按连接器使用 OM 原生字段，只暴露必填和常用项：MySQL / Doris 的数据库选填（`databaseSchema`，留空即全部库）；PostgreSQL / SQL Server 数据库必填（`database`，不采集全部库）；Oracle 用 Service Name；其他高级字段不暴露，原型同步修改。
- Q: 视图血缘要用哪个数据库来真实验收？003 的模拟库里没有任何视图。 → A: 在 `testdata/` 下新建独立的视图测试库（MySQL 与 PostgreSQL 各一，含若干引用基表的视图和一个读不到视图定义的只读账号），随 `make mock-data` 部署；003 数据集保持不变，不进入客户交付物。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 接入数据源并完成首次元数据采集 (Priority: P1)

数据工程与治理人员（`admin` / `ai-engineer`）在织境“数据接入 → 数据源”页面查看全部数据源汇总状态，通过四步配置向导新增或配置数据源（如模拟环境的 MES MySQL、QMS PostgreSQL、制造数仓 Doris，以及支持配置验证的 Oracle / SQL Server），填写只读数据库用户名与密码完成连接测试、设定采集范围与定时/手动调度计划，保存后在数据源详情的“采集任务”中触发首次采集，将源系统的库、Schema、表与字段结构真实采集写入 OpenMetadata。

**Why this priority**: 源系统元数据采集是后续资产搜索（006）、指标口径审批（015）、本体建模（016）和上下文交付（017）的数据地基；没有真实的连接配置与首次采集闭环，平台无法感知客户源库结构。

**Independent Test**: 在已部署模拟源系统（MES MySQL 13 张表 / 79 字段、QMS PostgreSQL 7 张表 / 53 字段、Doris `mock_dw` 8 张表 / 66 字段）的环境中，通过 `/sources` 页面完成数据源配置、连接测试、保存部署并触发采集，验证 28 张表、198 个字段及主键约束（Doris 键列按原生连接器记为主键）真实写入 OpenMetadata，且列表统计卡与详情页数据一致。

**Acceptance Scenarios**:

1. **Given** 用户已以具备管理权限的角色登录并打开 `/sources` 页面，**When** 查看数据源列表页，**Then** 页面按原型布局展示顶部 4 张汇总指标卡（已配置数据源、已采集表、字段元数据、需要关注）、搜索与状态筛选工具栏、数据源表格及底部提醒与架构说明卡。
2. **Given** 用户点击“添加数据源”（或对尚未完成配置的数据源点击“继续配置”），**When** 在步骤 1 填写显示名称、符合规则的服务标识并选择数据库连接器（MySQL / PostgreSQL / Doris / Oracle / SQL Server），在步骤 2 填写连接地址、端口、数据库参数、只读用户名与密码并点击“测试连接”，**Then** OpenMetadata 在采集执行环境中按该连接器的原生检查步骤真实校验，逐项返回步骤结果；若必需步骤失败则提示具体原因且阻止进入下一步，若连接成功后修改了任意连接参数则原测试通过状态自动失效。
3. **Given** 用户通过连接测试进入步骤 3 与步骤 4，**When** 设置采集范围（全部留空或数据库 / Schema / 表包含与排除过滤规则）、是否采集视图与是否创建视图血缘任务，并为每条任务选择调度方式（每天定时 `Asia/Shanghai` 或仅手动触发）后点击“保存配置”，**Then** 系统在 OpenMetadata 中保存 `DatabaseService` 与对应的元数据采集（及视图血缘）`IngestionPipeline`，并由 OpenMetadata 部署至独立 Airflow；部署失败时如实提示原因；关闭弹窗后在数据源详情页回显连接信息、采集范围与各任务调度。
4. **Given** 数据源已完成配置与任务部署，**When** 用户进入元数据采集任务的运行页并点击“立即运行”，**Then** Airflow 执行真实的 OpenMetadata 元数据采集，运行状态按 OpenMetadata 回写从排队中/采集中更新为成功（或部分成功/失败），采集完成后该数据源下符合过滤规则的数据库、Schema、表、字段注释、数据类型及主键约束全部可在目录与详情页查看，且全过程不读取或复制任何业务行数据。

### User Story 2 - 管理采集任务、调度启停、运行日志与异常后重新运行 (Priority: P1)

数据工程与治理人员在某个数据源详情的“采集任务”页签下查看该数据源的采集任务列表（元数据采集与可选的视图血缘），进入具体任务的运行记录页，按状态筛选运行历史、暂停或恢复该任务的定时调度、查看单次运行的原生步骤统计与失败对象，以及最近一次运行的脱敏日志；当某次运行因权限受限或网络异常出现“部分成功”或“失败”时，可依据失败原因排查修复后立即重新运行该任务，保留完整历史运行记录与已采集成功的表结构。

**Why this priority**: 生产环境中源库权限变更或网络抖动是常态，用户必须在数据源上下文内直观查看任务执行进度、诊断日志并控制定时调度与重新运行，而无需离开织境去操作底层编排系统。

**Independent Test**: 在已接入的数据源详情中进入“采集任务 → 运行”，分别执行暂停定时调度、恢复定时调度、手动立即运行、按状态筛选运行记录、打开“运行详情”弹窗查看步骤统计、失败对象与脱敏日志，以及制造权限/连接异常运行后修复并重新运行，验证状态流转与历史保留完整准确。

**Acceptance Scenarios**:

1. **Given** 用户进入某个已配置数据源的“采集任务”页签并点击任务进入“运行”视图，**When** 查看运行列表或使用状态下拉框筛选（全部状态 / 成功 / 部分成功 / 失败 / 采集中 / 排队中），**Then** 仅展示当前数据源当前任务的运行记录（切换任务或数据源不会混入其他任务的记录），每条记录准确显示开始时间、状态徽章、耗时与运行编号，数据全部来自 OpenMetadata `PipelineStatus`。
2. **Given** 某条任务配置为“每天定时”且处于启用状态，**When** 用户点击该任务的“暂停调度”并在确认弹窗中点击“确认暂停”，**Then** 经 OpenMetadata 使 Airflow 中对应 DAG 暂停自动调度（不影响同一数据源的另一条任务），界面状态更新为“已暂停”，已有元数据和历史运行记录完整保留，且用户仍可点击“立即运行”手动触发采集；再次点击“恢复调度”确认后恢复按原定时计划调度。
3. **Given** 某次采集运行完成或处于部分成功/失败状态，**When** 用户点击该次运行的“查看运行”打开“运行详情”弹窗，**Then** 弹窗展示开始时间、耗时、OpenMetadata 原生步骤统计（各步骤记录、更新、警告、错误、过滤数）与失败对象及原因；若为该任务最近一次运行，同时展示脱敏后的运行日志（不含任何密码明文或业务数据行），否则注明 OpenMetadata 仅提供最近一次运行日志。
4. **Given** 某次运行因读取权限不足等原因处于“部分成功”或“失败”，**When** 已采集的表和字段元数据仍在目录中正常保留，且用户在问题修复后点击“立即运行”，**Then** 系统为该任务发起一次新运行并保留此前的失败/部分成功历史记录，新运行成功后该任务最近运行状态更新为“成功”。

### User Story 3 - 浏览四层元数据目录与独立资产结构详情 (Priority: P1)

用户在左侧四层目录树（`服务 → 数据库 → Schema → 数据表`）或数据源详情的“已采集元数据”页签中逐层展开并浏览已采集的数据库、Schema、数据表与字段结构；选中数据库、Schema 或数据表时，右侧主区域切换为对应层级的独立资产详情视图（`METADATA CATALOG`），展示准确的层级面包屑、只读结构信息（表类型、字段数、主键约束）及字段列表，并支持一键返回所属数据源。

**Acceptance Scenarios**:

1. **Given** 数据源已完成采集，**When** 用户在左侧目录树展开数据源服务节点，或在数据源详情切换到“已采集元数据”页签，**Then** 目录树与列表真实反映 OpenMetadata 中的四层实体关系（`DatabaseService → Database → DatabaseSchema → Table`）；对于未完成首次采集的数据源，目录提示“未采集 / 暂无元数据”。
2. **Given** 用户在目录树或“已采集元数据”列表中点击某个数据库、Schema 或数据表，**When** 右侧展示该资产详情页，**Then** 页头眉标显示 `METADATA CATALOG`、标题显示该资产的显示名称（或物理名称）与完整 FQN，顶部显示 `← 返回所属数据源` 链接和截止到当前层级的面包屑（如选中数据库时面包屑仅到 `service › database`），且页面不显示数据源的连接配置按钮、采集页签或源级采集状态。

### User Story 4 - 维护数据源与各级资产的治理属性及继承关系 (Priority: P2)

数据工程与治理人员在数据源概览页、数据库详情页、Schema 详情页、数据表详情页以及字段行操作中，点击“编辑属性”弹窗维护显示名称、业务描述与治理属性（负责人、业务域、重要程度 Tier、分类标签、业务术语、数据产品、保留周期），系统按 OpenMetadata 2.0.3 原生规则校验并持久化属性，准确展示上下级继承关系，且后续重新运行元数据采集不会覆盖人工维护的治理属性。

**Why this priority**: 源库物理表名和注释往往简略或缺失，只有支持在数据源、库、Schema、表、字段各层级补充业务名称、描述与治理归属（并利用上下级继承减少重复录入），才能为下游数字员工与本体建模提供高可信上下文。

**Independent Test**: 依次在数据源、数据库、Schema、表和字段五个层级打开“编辑属性”弹窗，验证可选治理目录读取、保存回显、取消不保存、清空恢复继承、业务域与数据产品归属匹配校验、互斥分类标签替换、ISO 8601 保留周期校验，以及再次触发元数据采集后人工修改的属性不被覆盖。

**Acceptance Scenarios**:

1. **Given** 用户在数据源概览页点击“数据源属性 → 编辑属性”，**When** 修改显示名称、描述、负责人（多名用户或单个团队）、业务域（单选）、重要程度（`Tier.Tier1`–`Tier.Tier5`）、分类标签、业务术语、数据产品并保存，**Then** 修改持久化至 OpenMetadata `DatabaseService` 并立即在概览页与列表/目录树回显；后续修改数据源连接配置不会丢失已保存的治理属性。
2. **Given** 用户在数据库、Schema 或数据表详情页查看或编辑属性，**When** 上级已设置业务域（`服务 → 数据库 → Schema → 表`）、负责人（`数据库 → Schema → 表`，数据库不继承服务负责人）或保留周期（`数据库 → Schema → 表`）而当前层级未单独设置，**Then** 属性卡片自动展示继承值并标注 `继承自 <上级类型> · <上级 FQN>`；若当前层级单独设置则优先展示当前值并标注 `单独设置`；清空当前层级的单独设置后自动恢复继承上级。
3. **Given** 用户在属性编辑弹窗中选择数据产品、分类标签或填写保留周期，**When** 所选数据产品所属域与当前有效业务域（含继承域）不一致，或输入的保留周期不符合 ISO 8601 时长格式（如 `P30D`、`PT24H`），**Then** 弹窗内明确提示校验错误并阻止保存；当在同一互斥分类（如 `PII` 或 `PersonalData`）下勾选新标签时，自动替换同分类下的已选标签。
4. **Given** 用户在数据表详情的“字段元数据”表格中点击某字段行的“编辑属性”，**When** 修改该字段的显示名称、描述、分类标签与业务术语并保存，**Then** 修改通过所属表的列结构持久化至 OpenMetadata 并在该行回显，字段物理名称、数据类型与约束保持只读不变，且不影响其他表的同名字段；重新运行元数据采集后（`overrideMetadata=false`），已维护的显示名称、描述与标签保持不变。

### User Story 5 - 采集数据库视图定义并生成视图血缘 (Priority: P2)

当源系统中存在数据库视图，且数据源开启了“采集视图”并创建了视图血缘任务时，元数据采集任务读取视图元数据与视图定义，视图血缘任务再依据已采集的视图定义解析生成上游基表到视图的表级与字段级血缘写入 OpenMetadata；若源端权限不足或视图 SQL 无法解析，相应运行如实记录警告/部分成功状态及原因，不伪造血缘关系。

**Why this priority**: 数据库视图是源系统常见的逻辑封装层，自动提取视图到基表的表级和字段级血缘能够打通源系统内部的数据来源链路，同时在权限受限时给出来源可查的诊断信息。

**Independent Test**: 在 `testdata/` 下独立的视图测试库（MySQL 与 PostgreSQL 各一，不改动 003 数据集）上先运行元数据采集任务、再运行视图血缘任务，通过 OpenMetadata 血缘接口核对生成的上游表到视图的表级边与字段级映射（`columnsLineage`）；改用该测试库中无视图定义读取权限的只读账号运行采集，验证表与字段仍正常入库且运行结果明确提示视图定义读取受限。

**Acceptance Scenarios**:

1. **Given** 源数据库包含引用了同库基表的视图且数据源开启了“采集视图”并创建了视图血缘任务，**When** 元数据采集任务与随后的视图血缘任务均执行完成，**Then** 视图实体及其字段被采入 OpenMetadata，且 OpenMetadata 中生成从上游基表到该视图的准确表级血缘边与字段级血缘映射（零误报）。
2. **Given** 采集账号对表结构有只读权限但无法读取部分视图定义（或连接器/环境不支持视图定义提取），**When** 元数据采集与视图血缘任务执行完成，**Then** 所有可访问的表与字段元数据正常写入 OpenMetadata，相应运行的状态、失败对象与日志明确提示视图定义无法读取的原因，不因视图血缘受限而回滚已采集的表结构，也不臆造未证实的血缘边。

### Edge Cases

- **服务标识冲突或已采集源修改连接器**：新建数据源时若输入已存在的服务标识，向导在步骤 1 即时拦截并提示更换；对已有采集结果的数据源打开配置向导时，服务标识与连接器类型只读锁定，防止篡改底座实体身份导致历史资产错位。
- **连接参数修改后未重新测试连接**：在向导步骤 2 测试连接成功后，若用户修改了主机、端口、数据库名、用户名、密码或 TLS 选项，原测试结果立即失效，必须重新测试且必需步骤全部通过后才能继续。
- **测试连接与运行为异步执行**：OpenMetadata 的测试连接（由 Airflow 侧 OpenMetadata 插件执行）与采集运行（Airflow 每个任务一个 Pod）都是异步完成的，界面在等待期间显示进行中状态（测试中 / 排队中 / 采集中），完成后展示真实结果；超时或执行失败时展示真实错误，不显示为成功。
- **过滤规则不合法或未命中**：步骤 3 的包含 / 排除规则不是合法正则时阻止保存并提示具体规则；规则合法但未命中任何对象时，采集运行如实反映（过滤数或零记录），不补造对象。
- **视图血缘任务依赖视图采集**：未开启“采集视图”时不能创建视图血缘任务；关闭“采集视图”保存时一并移除视图血缘任务；视图血缘任务早于元数据采集运行时仅能基于已采集的视图定义，不臆造血缘。
- **无数据与依赖服务异常**：OpenMetadata 或 Airflow 不可用、部署或触发失败时，界面展示真实的错误信息，列表、统计与运行记录显示空状态或错误，MUST NOT 回退到内置示例数据或展示伪造的成功结果。
- **凭证脱敏与越权角色访问**：数据库密码由 OpenMetadata `SecretsManager` 加密存储，所有查询接口返回时自动脱敏（`*********`），不在列表、详情或日志中回显明文密码；非准入角色或无管理权限的用户调用写接口时，后端返回明确权限错误。
- **在途运行防重入**：当某个采集任务正处于“排队中（`queued`）”或“采集中（`running`）”时，界面禁用该任务的“立即运行”按钮，后端对并发重复触发请求予以拦截提示，防止同一任务并发重复执行；同一数据源的另一条任务不受影响。
- **父级业务域变更引发子级数据产品域冲突**：当上级实体修改业务域导致下级已关联的数据产品与新的有效业务域不一致时，下级属性卡片显式提示“当前域与数据产品不匹配，请编辑属性调整”，不会静默删除或篡改用户已关联的数据产品。
- **多层目录同名表隔离**：不同数据源或不同数据库/Schema 下存在同名表时，目录树、资产详情与属性编辑均按完整 FQN（`service.database.schema.table`）严格隔离，切换或修改互不串扰。
- **窄屏与移动端响应式布局**：在 `1280px`、`768px`、`390px` 视口宽度下，页面与弹窗均无整页横向溢出；宽表格在容器内横向滚动，窄屏下左侧目录树自动收起并通过顶栏“目录”按钮抽屉式打开。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001（数据源列表与汇总统计）**: 系统 MUST 在 `/sources` 提供与 HTML 原型一致的数据源列表页，包含顶部 4 张汇总统计卡（已配置数据源、已采集表、字段元数据、需要关注）、按关键字（名称/服务标识/连接器/库名）与状态（全部状态/采集成功/需要关注/待配置/调度已暂停）筛选的工具栏、数据源列表表格以及底部异常提醒卡与采集链路说明卡。
- **FR-002（四步接入与配置向导）**: 系统 MUST 提供四步弹窗向导（选择连接器 → 连接验证 → 采集范围 → 调度与确认），支持 `MySQL`、`PostgreSQL`、`Oracle`、`SQL Server`、`Doris` 五种连接器配置；连接表单 MUST 按连接器使用 OpenMetadata 2.0.3 原生连接字段（以各连接器 connection JSON Schema 为准），只暴露必填与常用项，库字段按连接器区分（MySQL / Doris 选填 `databaseSchema`；PostgreSQL / SQL Server 必填 `database` 且 `ingestAllDatabases=false`；Oracle 必填 Service Name）；认证直接对齐 OpenMetadata 原生 `username` + `password` 结构，密码由 OpenMetadata `SecretsManager` 加密托管，严禁在查询响应体、URL 或日志中回显与暴露数据库明文密码。
- **FR-003（真实连接测试与失效保护）**: 系统 MUST 支持在向导步骤 2 经 OpenMetadata 在采集执行环境中对所填连接参数执行该连接器的原生测试连接步骤（如 `CheckAccess`、`GetSchemas`、`GetTables`、`GetViews` 等，以 OpenMetadata 2.0.3 `testConnections` 定义为准），逐项展示步骤名称、必需/可选、结果与失败原因，不读取业务行；必需步骤未全部通过不得进入步骤 3；连接参数任意字段变更后，已有测试结果 MUST 自动失效。
- **FR-004（复用 OpenMetadata 与 Airflow 原生采集模型）**: 系统 MUST 复用 OpenMetadata 2.0.3 原生 `DatabaseService` 与 `IngestionPipeline` 实体存储数据源连接、采集范围（`databaseFilterPattern` / `schemaFilterPattern` / `tableFilterPattern` 的 `includes` / `excludes` 正则；全部为空即全部）与各任务调度配置，由 OpenMetadata 部署到独立 Airflow 并由 Airflow 执行 OpenMetadata 原生采集；BFF MUST NOT 自行执行采集或写入运行状态，运行状态 MUST 以 OpenMetadata `PipelineStatus` 为准；采集配置 MUST 强制关闭数据采样（`generateSampleData=false`、`extractJsonSchema=false`）、数据剖析（profiler）与自动软删除历史表（`markDeletedTables=false`），确保只读采集元数据、零业务行复制。
- **FR-005（数据源详情四页签与任务运行控制）**: 系统 MUST 在数据源详情页提供“概览”、“已采集元数据”、“采集配置”、“采集任务”四个页签；每个已配置数据源有一条元数据采集任务（`pipelineType=metadata`）及可选的一条视图血缘任务（`pipelineType=lineage`），任务按 OpenMetadata 规则命名 `<服务标识>_<类型>_<8 位随机串>`；在“采集任务”下支持查看任务列表、进入单个任务的运行记录页、按状态筛选运行历史、手动立即运行、暂停/恢复该任务定时调度（带确认弹窗）、查看 Airflow 调度关联详情，以及在“运行详情”弹窗中查看 OpenMetadata 原生步骤统计、失败对象、最近一次运行的脱敏日志，并在异常后立即重新运行。
- **FR-006（四层元数据目录与独立下级资产详情）**: 系统 MUST 在左侧导航栏及“已采集元数据”页签提供按 OpenMetadata 实际实体层级组织的四层目录（`数据源服务 → 数据库 → Schema → 数据表`）；点击数据库、Schema 或数据表时 MUST 展示独立的 `METADATA CATALOG` 资产详情页（含返回所属数据源链接、精确到当前层级的面包屑、下级子项列表或表的只读结构信息与字段列表），下级资产详情页 MUST NOT 混入数据源连接配置、采集页签或采集运行控制按钮。
- **FR-007（数据源与下级资产治理属性维护及继承）**: 系统 MUST 支持在数据源、数据库、Schema、数据表四个层级编辑显示名称、描述、负责人（多用户或单团队）、业务域（单选）、重要程度（`Tier.Tier1`–`Tier.Tier5`）、分类标签、业务术语与数据产品，并在数据库、Schema、数据表层级支持编辑 ISO 8601 保留周期（`retentionPeriod`）；在字段层级支持编辑显示名称、描述、分类标签与业务术语。系统 MUST 遵循 OpenMetadata 2.0.3 原生继承规则（业务域沿`服务→库→Schema→表`继承；负责人与保留周期沿`库→Schema→表`继承），在界面明确标注“单独设置”或“继承自 `<上级>`”，且重新采集元数据（`overrideMetadata=false`）不得覆盖人工维护的属性。
- **FR-008（治理选项动态读取与校验）**: 属性编辑弹窗中的可选人员、团队、业务域、分类标签、业务术语与数据产品 MUST 通过 BFF 从 OpenMetadata 实时读取；保存时 MUST 校验数据产品与当前有效业务域一致、同一互斥分类下标签单选、保留周期符合 ISO 8601 时长格式。
- **FR-009（数据库视图血缘采集）**: 当数据源开启“采集视图”（`includeViews=true`）并创建视图血缘任务时，元数据采集任务 MUST 采集视图元数据与视图定义（`schemaDefinition`），视图血缘任务 MUST 以 OpenMetadata 原生 lineage 采集（`processViewLineage=true`、`processQueryLineage=false`，本期不处理查询日志血缘）依据已采集的视图定义生成上游表到视图的表级与字段级血缘写入 OpenMetadata；当视图定义不可读或解析受限时，MUST 保留已采集的表与字段元数据，按 OpenMetadata 原生状态如实记录（如 `partialSuccess`）及失败对象与原因，不得伪造血缘关系。
- **FR-010（架构与安全边界）**: 浏览器 MUST 仅通过织境 BFF 访问后端能力，不得直连 OpenMetadata、Airflow 或源系统数据库；BFF 不得直接持有业务数据库账号密码查询业务库；所有写操作（新增/修改数据源、触发/启停采集任务、修改治理属性）MUST 校验用户角色权限并留存含 `trace_id` 与 `tenant_id` 的结构化审计日志。

### Key Entities *(include if feature involves data)*

遵循项目宪法原则 VII（数据模型优先复用，非必要不新增实体），本特性**不新建任何平行持久化业务表**，全部复用 OpenMetadata 2.0.3 与 Airflow 原生实体：

- **数据源服务（`DatabaseService`）**: 代表一个接入的源数据库系统（如 `mock-mes`、`mock-qms`、`mock-dw`），承载连接器类型、OpenMetadata 原生连接配置（`hostPort`、`username`、经 `SecretsManager` 加密托管的 `password`、数据库/Schema 参数、SSL 配置）、显示名称、描述及服务级治理属性（负责人、业务域、Tier、分类标签、业务术语、数据产品）。
- **采集任务与运行状态（`IngestionPipeline` & `PipelineStatus`）**: 归属于具体 `DatabaseService` 的采集管道，本期两类：元数据采集（`metadata`，承载过滤规则、`includeViews` 等采集配置）与可选的视图血缘（`lineage`，`processViewLineage=true`、`processQueryLineage=false`）；各自承载调度计划（手动或每日定时 `Asia/Shanghai`）与启停状态，以及在 Airflow 中执行的历次运行状态（`runId`、`pipelineState`：`queued` / `running` / `success` / `partialSuccess` / `failed` / `stopped`、`startDate`、`endDate`、步骤统计 `status`），最近一次运行日志经 OpenMetadata 读取。
- **数据库（`Database`）与 Schema（`DatabaseSchema`）**: 数据源下已采集的逻辑/物理库与 Schema 节点，承载自身及从上级继承的治理属性与保留周期，并聚合下级对象统计。
- **数据表/视图（`Table`）与字段（`Column`）**: 已采集的表或视图结构实体，包含表类型（`Regular` / `View`）、OpenMetadata 原生连接器采集到的约束（`PRIMARY_KEY` 等；Doris 键列记为主键）、视图定义（`schemaDefinition`）、表级治理属性，以及嵌套的 `columns` 字段列表（字段名、数据类型、主键成员标识、显示名称、描述、分类标签、业务术语）。
- **视图血缘边（`LineageEdge` / `ColumnLineage`）**: 由视图定义解析产生的上游基表到视图的表级依赖关系及字段级映射关系，存储于 OpenMetadata 原生血缘图中。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001（模拟源全量准确采集）**: 在本地集群环境中，通过织境 Web 界面完成 `003` 模拟工厂三个源系统（MES MySQL、QMS PostgreSQL、数仓 Doris）的接入与采集后，OpenMetadata 中准确入库全部 **28 张表、198 个字段**及其字段类型、注释与主键约束（Doris 键列按原生连接器记为主键），数量与结构准确率达到 **100%**。
- **SC-002（接入与首采操作效率）**: 管理员从打开“添加数据源”向导、完成连接测试、保存配置到触发首次采集并在目录中查看到采集结果，端到端操作可在 **3 分钟内**完成。
- **SC-003（任务控制与异常可观测性）**: 两类采集任务的手动运行、定时暂停/恢复、按状态筛选、步骤统计与失败对象查看、最近一次运行脱敏日志查看以及异常修复后重新运行的准确率达到 **100%**，且页面展示的运行记录与 OpenMetadata `PipelineStatus` 一致；单次采集异常不会破坏已入库元数据或丢失历史运行记录。
- **SC-004（五层级属性维护与重采保护）**: 在数据源、数据库、Schema、数据表、字段五个层级编辑显示名称、描述与治理属性（含业务域、负责人、保留周期的上下级继承与恢复）后，属性回显准确率达到 **100%**，且再次执行元数据采集后人工维护属性的保留率达到 **100%**。
- **SC-005（视图血缘准确性）**: 对 `testdata/` 下独立视图测试库（MySQL / PostgreSQL）中已启用视图血缘且具备视图定义读取权限的场景，视图到上游基表的表级血缘边与字段级血缘映射准确率达到 **100%**，未授权或不可解析场景下误报率为 **0%**。
- **SC-006（只读与零数据泄漏红线）**: 采集与连接测试全过程中，对源系统的写操作数为 **0**，业务行采样/复制数为 **0**，前端网络响应与运行日志中的明文密码泄漏数为 **0**。
- **SC-007（原型一致性与多视口响应式还原）**: 生产 Web 页面在信息架构、四步向导、统计卡片、详情四页签、独立下级资产页及属性弹窗的页面结构、交互流程、状态种类与文案风格上与确认的 HTML 原型保持一致（页面上的数字、时间、运行记录与表结构全部来自真实来源，不沿用原型示例值），且在 `1280px`、`768px`、`390px` 三种视口宽度下整页横向溢出数为 **0**。

## Assumptions

- **凭证安全托管**: 源系统数据库的只读账号与密码按 OpenMetadata 2.0.3 原生连接表单配置，由 OpenMetadata 内置 `SecretsManager`（Fernet 加密存储）统一托管并在所有查询接口响应与运行日志中自动脱敏（`*********`），BFF 不保存数据库密码也不直连业务数据库。
- **五类连接器验证边界**: 本特性在产品界面、契约与连接配置上完整支持 `MySQL`、`PostgreSQL`、`Doris`、`Oracle`、`SQL Server` 五种连接器；本地自动化集成与端到端验收以集群内已具备真实实例的 `MySQL`（MES）、`PostgreSQL`（QMS）、`Doris`（`mock_dw`）为必选实测基线，Oracle 与 SQL Server 在无本地真实实例时通过连接配置契约与单元测试覆盖并在验收文档中如实注明环境限制。
- **视图血缘测试数据**: 003 模拟库不含视图；视图血缘与“视图定义不可读”场景使用 `testdata/` 下新建的独立视图测试库（MySQL 与 PostgreSQL 各一，含若干引用同库基表的视图，以及一个无法读取视图定义的只读账号），随 `make mock-data` 部署，不进入客户交付物；003 的 28 张表 / 198 个字段数据集与 SC-001 计数保持不变。
- **范围边界**: 国产数据库（达梦、人大金仓、OceanBase、GaussDB）适配与评估已明确移出本特性；帆软报表 SQL 血缘解析及独立模块已明确暂缓；全局跨源资产搜索归 `006-asset-search`，Agent 页面助手归 `007`，治理审批流归 `008`。
