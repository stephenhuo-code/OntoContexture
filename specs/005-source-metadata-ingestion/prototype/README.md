- 保留数据源接入和“服务 → 数据库 → Schema → 表”的多层目录。
- 采集管理收进 **数据源详情 → 采集任务 → 运行**，不设全局“采集运行”入口。
- 2026-11-04 补充确认：帆软 SQL 血缘解析及写入交付本次暂缓，独立模块和入口均不纳入 005；保留调研，后续另行确定。
- Agent 暂不做；2026-11-04 确认移除国产数据库接入适配及评估，不纳入 005。
- 配置向导移除业务域；每个数据源在概览的“数据源属性”中编辑名称、描述与 OM 治理属性。
- 数据库 / Schema / 表详情支持显示名称、描述、负责人、域、Tier、标签、术语、数据产品和保留周期编辑；字段支持显示名称、描述、标签与术语编辑。结构信息只读。
- 采集配置与运行仅在数据源详情中管理。数据库 / Schema / 表使用独立资产详情页头，不显示数据源的采集状态、连接配置和采集页签；可返回所属数据源。

负责人决定“尽量与 OM 一致，第一期不加功能”，原型据此调整，依据见 [OM 对齐记录第 9 节](openmetadata-alignment.md)：

- 采集任务按 OM 原生拆为元数据采集与视图血缘两条，各自调度与运行；运行记录按 OM `PipelineStatus` 展示（UUID 运行编号，无触发方式），详情为步骤统计、失败对象与最近一次运行日志；异常后通过“立即运行”重新运行。
- Doris 按原生连接器显示主键约束，不显示 UNIQUE / UK。

## 建议体验路径

1. **左侧目录 → mock-qms → qms → public → ncr**：展开目录，查看表字段、类型、主键和说明。选中数据库或 Schema 查看子项；窄窗口通过顶部“目录”按钮打开。
2. **QMS → 采集任务**：查看“元数据采集”与“视图血缘”两条任务。进入元数据采集任务的“部分成功”运行，查看步骤统计、失败对象（示例）与日志；勾选“原型演示：模拟源端权限已修复”后点击“立即运行”，生成新的成功运行，旧记录保留。
3. **当前任务的运行页 → 暂停 / 恢复调度**：两条任务各自调度；状态筛选只作用于当前任务。切换任务或数据源后不会混入其他运行记录。
4. **ERP → 继续配置**：填写示例主机、用户名与密码，测试连接并查看 OM 原生检查步骤（可勾选“连接不可达”演示失败）；按数据库 / Schema / 表过滤规则设置范围（如表包含 `^erp_material$`），选择是否创建视图血缘任务并分别设置调度，保存后进入采集任务触发首次采集。
5. 运行页可返回采集任务列表，再切换概览、采集配置或已采集元数据；多层目录的选择与字段详情联动。
6. **任意数据源 → 概览 → 编辑属性**：编辑显示名称、描述，选择负责人、业务域、重要程度、标签、术语和数据产品。保存后在概览回显；取消不保存；可取消关联。选择“示例业务域 A”和“示例数据产品 A”可保存；改成域 B 后仍保留产品 A，会提示不匹配，需调整后再保存。
7. **多层目录 → qms 数据库 → 编辑属性**：设置显示名称、负责人和保留周期（如 `P30D`）；进入 `public` Schema 或 `ncr` 表，查看继承来源。在 Schema 单独设置域或周期后，表显示新的继承来源；清除单独设置可恢复继承。
8. **ncr 表 → 字段元数据 → ncr_no 行 → 编辑属性**：修改显示名称、描述、分类标签和术语，保存后在行内回显。字段名称和类型保持不变；切换其他表不混入此字段的修改。
9. **数据源 → 已采集元数据 → 数据库目录**：逐层打开库 / Schema / 表。下级页面显示当前资产名称、属性和结构，不显示采集配置、任务或源级状态；点“返回所属数据源”后再进入“采集任务 → 运行”。

## 设计边界

- 沿用织境浅色工作台风格，生产外壳未修改。表字段定义来自 `testdata/mockfactory/schema/`：MES 13 张表 / 79 个字段，QMS 7 张表 / 53 个字段，Doris 数仓 8 张表 / 66 个字段。状态、时间和权限异常为示例。
- ERP 尚无测试设施，向导中的 Oracle 和两张表仅为设计示例；新增 SQL Server / Oracle 也使用这些示例，不能据此认定真实数据库已接通。
- 连接测试、配置、调度、运行和元数据写入全部在浏览器内存中模拟。未连接真实数据库、Airflow 或 OM，不执行业务 SQL，不复制业务行。
- 凭证仅展示引用，不收集密码。不包含采样、剖析或自动删除历史元数据。
- 目录表示已采集结果，不是实时浏览源库。未采集源显示“未采集”。MySQL / Doris 示例使用 `default` 目录数据库与物理库对应的 Schema，生产以 OM 实际返回层级为准。
- 每个已配置数据源有一条元数据采集任务（`<service>_metadata_<随机串>`）及可选的视图血缘任务（`<service>_lineage_<随机串>`），在“数据源详情 → 采集任务 → 运行”中管理立即运行、暂停 / 恢复与日志；不新增全局任务或报表模块。
- 资产搜索与摘要归后续 006，Agent 归 007。指标管理、完整治理与业务数据物化未纳入当前原型。
- 帆软范围以 2026-11-04 的补充确认为准：本次暂缓解析交付，只保留调研结论，不自动安排到其他特性编号。
- 治理选项明确标注为离线示例，不代表已创建企业业务域或人员。初始源不分配治理属性；生产需读取 OM 已有实体与实际规则。原型使用 OM 默认规则：域单选、负责人为多名用户或一个团队、产品与域一致；PII / PersonalData 同分类互斥。属性编辑不触发采集，也不创建治理实体。
- 继承规则按锁定源码实现：业务域沿服务 → 库 → Schema → 表继承；负责人从库 → Schema → 表继承，库不继承服务负责人；保留周期从库向下继承。显示明确的继承来源，单独设置优先；清空后恢复继承。字段不增加 OM Schema 未定义的负责人、域或产品属性。
- 表约束以示例源建表定义为准；Doris 键列按 OM 原生 Doris 连接器显示为 PRIMARY_KEY / PK，不识别 UNIQUE KEY（本期不做）。未提供的外键、分区与视图定义不伪造。保留周期只修改元数据，不删除业务数据。所有操作仍是离线模拟，不是 OM 集成完成。
- OM 的元数据采集任务属于数据源服务，范围可过滤库 / Schema / 表；目录里的数据库对象不是任务管理层级。原型按此分离源管理与资产浏览，详见调研第 8 节。
