# Feature Specification: DOKS 云端开发与部署环境（DigitalOcean Kubernetes Dev & Deploy）

**Feature Branch**: `030-doks-deploy`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "在保留现有 kind 本地部署方式（make up / ENV=local|lite）不变的前提下，新增一套独立的 DigitalOcean Kubernetes（DOKS）部署方式，并以 DOKS 作为开发环境。决定（来自产品负责人，2026-11-10）：1) 复用开发机 devbox-0 所在的现有 DOKS 集群，弹性节点池 4 核 8 GB × 最多 6 个节点；2) Keycloak 在集群内自带部署，导入 contexture 领域与测试用户；3) 对外访问使用自有域名 + HTTPS；4) 共享环境镜像由 GitHub Actions 手动触发构建并推送到 DOCR；5) DO 作为开发环境：开发机不扩容、不装 Docker，编译、构建、运行与测试均在集群内完成；6) 开发 namespace 只部署 bff 和 web，其余组件共用共享环境的 OpenMetadata、Doris、Keycloak 等；7) OpenMetadata 相关的 3 个镜像只用 GitHub Actions 构建，集群内只构建 bff 和 web 这类小镜像。"

---

## 背景与范围

织境目前只有一种部署方式：在开发者本机用 kind 创建集群，本机构建镜像后导入集群，借用本机 Paperclip 的 Keycloak（`sso.127.0.0.1.nip.io`，自签 CA），入口经 NodePort 映射到本机 `localhost:8080`。这要求开发者有一台装 Docker、内存充足的电脑。

负责人的开发机 devbox-0 运行在 DOKS 集群中（容器限额约 1.5 核、2 GB 内存，无 Docker，主目录在持久卷上）。它无法运行 kind、构建镜像或承载织境组件，但与集群在同一网络内。

本特性在 DOKS 上建立两类环境，使负责人**以 DOKS 作为开发环境**：

1. **共享环境**：完整的一套织境平台（含集群内自带的 Keycloak），通过公网域名 HTTPS 访问，用于演示与产品负责人验收；镜像来自 GitHub Actions。
2. **开发环境**：一个开发 namespace，只运行开发中的 bff 与 web，其余组件共用共享环境；开发机上的代码改动**不经 git 推送**即可在开发环境中生效，构建与测试都在集群内执行，开发机只负责编辑代码和发出命令。

完成开发和测试后，负责人可以用一条命令**停止**云端织境环境：弹性节点池中的节点被释放，只保留运行 devbox-0 的固定开发节点，以节省费用；再用一条命令**启动**，环境恢复到停止前的状态，数据不丢失。

现有 kind 部署（`make up`、`ENV=local|lite`、离线安装包）的行为与入口**保持不变**。

**本期不做**：多名开发者各自的开发 namespace（本期只有一个开发 namespace）、dev / staging 多级环境、多租户、客户生产交付、在 DOKS 上运行离线安装包、集群本身的创建与节点池调整（复用已有集群）、监控告警外发、在集群内构建 OpenMetadata 相关镜像。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 运维者一条命令部署共享环境 (Priority: P1)

运维者（当前为产品负责人）在开发机 devbox-0 上准备好云端配置后，执行一条部署命令，即可在现有 DOKS 集群的共享 namespace 中拉起织境全部平台组件（含集群内自带的 Keycloak），并在结束时看到各组件冒烟测试结果。重复执行可安全地更新到指定版本，不会重置已有数据与密码。

**Why this priority**: 共享环境同时是开发环境所依赖的组件底座，没有它其余故事都无法进行。

**Independent Test**: 在已配置凭证的开发机上执行部署命令，命令结束时所有组件冒烟测试通过，且织境资源全部位于共享 namespace 内。

**Acceptance Scenarios**:

1. **Given** 开发机已具备部署工具与集群访问凭证、云端配置文件已填写，**When** 运维者执行共享环境部署命令，**Then** 全部平台组件在共享 namespace 内就绪，命令输出各组件冒烟测试通过并给出访问地址。
2. **Given** 共享环境已部署且有数据（如已接入的数据源、Langfuse 轨迹），**When** 运维者再次执行部署命令，**Then** 组件被更新，已有数据、数据库密码与自动生成的密钥保持不变。
3. **Given** 缺少必需配置项（如域名、镜像仓库凭证），**When** 运维者执行部署命令，**Then** 命令在修改集群之前即失败，并明确指出缺少哪一项。
4. **Given** 开发机 kubeconfig 的当前上下文指向其他集群，**When** 运维者执行部署命令，**Then** 命令只作用于云端配置中指定的集群与 namespace。

### User Story 2 - 开发者改代码后几秒内在开发环境看到效果 (Priority: P1)

开发者在 devbox-0 上修改 bff 或 web 的源代码并保存，无需提交或推送 git、无需重新构建镜像，几秒内开发环境中运行的 bff / web 就加载了新代码；开发者在浏览器中打开开发环境的域名，登录后即可看到改动，页面取数来自共享环境的真实组件。

**Why this priority**: 这是“以 DOKS 作为开发环境”的核心价值，决定日常开发效率。

**Independent Test**: 启动开发模式后修改 bff 的一个接口返回文案与 web 的一处页面文字，10 秒内在开发环境域名中看到两处变化，期间没有产生 git 提交与镜像构建。

**Acceptance Scenarios**:

1. **Given** 共享环境已部署，**When** 开发者在 devbox 上执行开发模式启动命令，**Then** 开发 namespace 中的 bff 与 web 以开发模式运行，命令持续运行并显示其日志。
2. **Given** 开发模式运行中，**When** 开发者保存 bff 或 web 的源文件，**Then** 改动在 10 秒内于开发环境生效，不产生 git 提交、不构建镜像。
3. **Given** 开发模式运行中，**When** 开发者访问 `https://<开发环境域名>` 并用测试用户登录，**Then** 登录经共享环境的 Keycloak 完成，页面数据来自共享环境的 OpenMetadata、Doris 等组件。
4. **Given** 开发者修改了依赖声明（如 Python 或前端依赖），**When** 保存后，**Then** 开发环境中的运行进程更新依赖后重新加载，或明确提示需要重建并给出命令。
5. **Given** 开发者结束开发模式，**When** 停止命令，**Then** 开发环境的 bff / web 停止或恢复为上一次部署的版本，共享环境不受影响。

### User Story 3 - 开发者在集群内运行检查与测试 (Priority: P1)

开发者在 devbox-0 上执行一条命令，对开发机上**当前工作区**（含未提交改动）运行代码检查、单元 / 契约测试与覆盖率、集成测试或端到端测试；这些检查在集群内执行，结果与失败详情实时输出到开发机终端，退出状态反映成败。

**Why this priority**: 宪法要求测试先行、交付前跑完全部自动化验证；开发机资源不足以运行它们，没有这一能力就无法按流程开发。

**Independent Test**: 故意让一个单元测试失败后执行测试命令，终端显示失败详情且命令以失败状态退出；修复后再执行，命令成功退出并显示覆盖率。

**Acceptance Scenarios**:

1. **Given** 开发机工作区含未提交改动，**When** 开发者执行集群内检查命令（对应本地 `make lint`），**Then** 检查基于当前工作区运行，结果输出到终端，退出状态与检查结果一致。
2. **Given** 同上，**When** 开发者执行集群内测试命令（对应本地 `make test`），**Then** 单元、契约与集成测试在集群内运行，集成测试使用真实依赖，终端输出测试结果与覆盖率。
3. **Given** 开发环境已运行，**When** 开发者执行集群内端到端测试命令（对应本地 `make e2e`），**Then** 端到端测试针对开发环境运行并输出结果。
4. **Given** 测试运行中开发者中断命令，**When** 命令退出，**Then** 集群内为该次运行创建的临时资源被清理。

---

### User Story 4 - 团队通过域名以 HTTPS 访问共享环境 (Priority: P2)

团队成员在浏览器中打开织境共享环境的公网域名，经 HTTPS 访问织境 Web，跳转到集群内的 Keycloak 登录后正常使用已有功能；也可通过子域名打开各组件界面。

**Why this priority**: 演示与验收依赖此能力，但开发环境的访问（US2）已覆盖开发者自身需求。

**Independent Test**: 用任一测试用户在浏览器打开共享环境域名，完成登录并进入首页；浏览器显示受信任的证书。

**Acceptance Scenarios**:

1. **Given** 共享环境已部署、域名已解析到负载均衡器，**When** 用户访问 `https://<织境域名>`，**Then** 页面通过受信任的 HTTPS 证书加载，未登录时跳转到 Keycloak 登录页。
2. **Given** 用户在 Keycloak 登录页输入有效凭证，**When** 登录成功，**Then** 返回织境 Web 并显示该用户的会话信息。
3. **Given** 用户以 HTTP 访问织境域名，**When** 请求到达入口，**Then** 被重定向到 HTTPS。
4. **Given** 共享环境已部署，**When** 用户访问 `https://<组件子域名>`（如 OpenMetadata、Langfuse、Airflow），**Then** 以受信任证书打开对应组件界面，登录方式与本地环境一致。
5. **Given** 证书即将到期，**When** 到达自动续期时间，**Then** 证书自动续期，无需人工操作。

---

### User Story 5 - 镜像构建：小镜像集群内构建，OpenMetadata 镜像由流水线构建 (Priority: P2)

开发者需要验证 Dockerfile、依赖或 Chart 的改动时，在 devbox 上执行一条命令，即可基于当前工作区在集群内构建 bff / web 镜像并部署到开发环境，不经 git。共享环境使用的全部 5 个自建镜像，以及 OpenMetadata 相关的 3 个镜像（openmetadata-server、openmetadata-fuseki、openmetadata-ingestion-airflow），由手动触发的 GitHub Actions 流水线构建并推送到 DOCR。

**Why this priority**: 日常改动走 US2 的文件同步即可，镜像构建只在改动构建方式或发布到共享环境时需要。

**Independent Test**: 修改 bff 的 Dockerfile 后执行集群内构建命令，开发环境中运行的 bff 镜像为新构建的版本；对某个提交手动触发流水线后，DOCR 中出现以该提交标识为标签的全部自建镜像。

**Acceptance Scenarios**:

1. **Given** 开发机工作区含未提交的 bff 或 web 改动，**When** 开发者执行集群内构建部署命令，**Then** 集群内基于该工作区构建 bff / web 镜像、推送到 DOCR 并更新开发环境，全程不需要开发机上的 Docker。
2. **Given** 运维者对某个分支或提交手动触发流水线，**When** 流水线运行完成，**Then** DOCR 中出现该提交对应标签的 bff、web、openmetadata-server、openmetadata-fuseki、openmetadata-ingestion-airflow 镜像。
3. **Given** OpenMetadata 上游版本未变化，**When** 流水线运行，**Then** 不重复构建已存在的同版本 OpenMetadata 相关镜像。
4. **Given** 运维者在部署共享环境时指定镜像版本，**When** 部署完成，**Then** 集群中自建服务运行的正是该版本。
5. **Given** 镜像构建失败，**When** 流水线或集群内构建结束，**Then** 以失败状态结束，不推送不完整的镜像集合，不更新正在运行的环境。

### User Story 6 - 云端环境可查看、可排障、可卸载 (Priority: P3)

运维者能查看云端织境各组件的访问方式与凭证位置用于手动验收与排障，并能分别卸载开发环境或共享环境，不影响集群中的其他工作负载（包括开发机 devbox-0 自身）。

**Why this priority**: 运维便利与安全退出，不阻塞核心价值。

**Independent Test**: 执行查看命令后可获得各组件访问方式；执行卸载命令后对应 namespace 及其资源被删除，devbox-0 与集群中其他 namespace 不受影响。

**Acceptance Scenarios**:

1. **Given** 云端环境已部署，**When** 运维者执行组件信息查看命令，**Then** 输出各组件的访问地址与凭证位置，覆盖本地 `make ports` 提供的全部组件。
2. **Given** 开发环境与共享环境均已部署，**When** 运维者卸载开发环境并确认，**Then** 只删除开发 namespace 的资源，共享环境与其数据不受影响。
3. **Given** 共享环境已部署，**When** 运维者卸载共享环境并确认，**Then** 共享 namespace 内的工作负载、负载均衡器与持久卷被清理，集群中其他 namespace 的资源（含 devbox-0 及其持久卷）保持不变。
4. **Given** 运维者执行卸载命令但未确认，**When** 命令结束，**Then** 不删除任何资源。

---

### User Story 7 - 一条命令启停云端环境，空闲时释放弹性池 (Priority: P2)

负责人完成一天的开发和测试后，在 devbox-0 上执行停止命令：云端织境的全部工作负载（共享环境、开发环境、集群内构建与测试）停止运行，弹性节点池的节点随之释放，集群中只剩运行 devbox-0 的固定开发节点。下次开始工作时执行启动命令，环境恢复到停止前的状态，已有数据、配置与登录凭证都在。负责人随时可以查看环境当前是运行中还是已停止，以及弹性池还剩几个节点。

**Why this priority**: 弹性池节点按运行时间计费，空闲时释放能显著降低费用；但它不影响开发与部署的核心功能，故次于 P1。

**Independent Test**: 在环境运行且有数据时执行停止命令，命令结束后弹性池节点数降到最小值，devbox-0 不受影响；再执行启动命令，全部冒烟测试通过，停止前接入的数据源与元数据仍在。

**Acceptance Scenarios**:

1. **Given** 云端环境运行中，**When** 负责人执行停止命令，**Then** 织境在弹性池上的所有工作负载停止，命令等待弹性池节点释放到最小节点数后结束，并输出停止后的节点数；devbox-0 与固定开发节点不受影响。
2. **Given** 云端环境已停止，**When** 负责人执行启动命令，**Then** 弹性池按需扩容，共享环境与开发环境恢复运行，冒烟测试通过，命令输出访问地址。
3. **Given** 停止前环境中已有数据（已接入的数据源、OpenMetadata 元数据、Langfuse 轨迹、Keycloak 用户），**When** 停止后再启动，**Then** 数据 100% 保留，所有用户可用原凭证登录，访问域名不变。
4. **Given** 任意状态，**When** 负责人执行状态查看命令，**Then** 显示共享环境与开发环境各自是运行中、已停止还是部分运行，以及弹性池当前节点数。
5. **Given** 环境已停止，**When** 再次执行停止命令，**Then** 命令直接报告已停止并成功结束；运行中再次执行启动命令同理。
6. **Given** 有资源阻止弹性池节点释放（如不在织境控制下的工作负载占用弹性池节点），**When** 停止命令等待超过上限，**Then** 命令报告是哪些资源阻止了释放，而不是一直等待或误报成功。

### Edge Cases

- 弹性节点池需要扩容才能容纳组件、构建或测试任务时，命令等待节点扩容完成而不是立即超时；超过等待上限仍无法调度时，报告是哪个组件或任务因资源不足无法启动。
- 共享环境未部署或未就绪时启动开发模式：命令立即失败并提示先部署共享环境。
- 共享环境升级（组件版本或接口变化）后，开发环境中的 bff / web 与之不兼容：冒烟检查应能暴露问题，而不是静默出错。
- 开发环境与共享环境的 bff 同时运行：两者的会话与 bff 自有数据互不干扰（见 FR-012）。
- 开发机与集群之间的网络中断：文件同步恢复后自动补齐改动，或明确提示需要重启开发模式。
- 集群内测试或构建被中断：临时资源被清理，不在集群中留下长期占用资源的残留 Pod 或卷。
- 域名尚未解析到负载均衡器时证书无法签发：命令须提示所需的 DNS 记录（记录类型、名称、目标地址）。
- 重复部署时，已生成的数据库密码、加密密钥、Langfuse 初始密钥不得被重新生成。
- 集群中已有同名 CRD 或控制器（如 Gateway API、Envoy Gateway、CloudNativePG、Doris Operator）由其他工作负载安装时，部署不得覆盖或破坏其现有版本；冲突时停止并报告。
- DOCR 拉取凭证失效或镜像标签不存在时，冒烟测试结果能看出是镜像拉取问题。
- 持久卷只支持单节点读写（RWO）时，需要多副本共享卷的组件不得以多副本共享同一卷的方式部署。
- 停止时有集群内测试、镜像构建或开发模式正在运行：停止命令先提示并要求确认，确认后终止这些任务再停止环境。
- 停止期间到达定时采集时间（Airflow 调度的元数据采集）：该次采集不执行；启动后按调度继续，不补跑停止期间错过的采集。
- 停止时间较长，期间证书到期：启动后证书自动重新签发或续期，启动命令在证书可用前不报告成功。
- 启动时弹性池扩容失败或节点不足：启动命令报告哪些组件无法调度，已启动的组件保持运行，可重新执行启动命令继续。
- 停止命令中途失败（如网络中断）：环境处于部分运行状态，状态命令能如实显示；重新执行停止或启动命令能把环境收敛到目标状态。

## Requirements *(mandatory)*

### Functional Requirements

**环境划分与隔离**

- **FR-001**: 系统 MUST 提供独立于 kind 的云端部署入口；现有 `make up`、`make down`、`ENV=local|lite` 与离线安装的行为 MUST 保持不变。
- **FR-002**: 云端 MUST 包含两个 namespace：共享环境（完整平台）与开发环境（只运行 bff 与 web）。所有云端命令 MUST 以显式指定的集群上下文与 namespace 执行，MUST NOT 依赖或改变 kubeconfig 的当前上下文。
- **FR-003**: 共享环境的部署 MUST 可重复执行（幂等）：已存在的自动生成密钥与数据库密码 MUST NOT 被重新生成，已有持久数据 MUST 保留。
- **FR-004**: 云端命令 MUST 在修改集群前校验必需配置（集群上下文、namespace、域名、镜像仓库与镜像版本、凭证），缺失时给出明确报错并退出。
- **FR-005**: 云端环境的凭证 MUST 来自开发机上不纳入版本控制的配置文件，并与本地 kind 环境的凭证文件分开；凭证 MUST NOT 写入仓库、镜像或命令输出。
- **FR-006**: 共享环境的组件集合 MUST 与本地 `make up` 部署的平台组件一致（不含 003 模拟源系统，见 FR-024），并新增集群内自带的 Keycloak。

**身份（Keycloak）**

- **FR-007**: 共享环境 MUST 在其 namespace 内自带部署 Keycloak，使用平台内 PostgreSQL 存储，不依赖开发机或 Paperclip 的任何服务。
- **FR-008**: 部署 MUST 自动导入织境所需的 realm 配置与客户端（与本地环境相同的客户端定义），使 bff、OpenMetadata、AI 网关以该 Keycloak 作为受信 IdP；开发环境的访问地址 MUST 登记为 bff 客户端允许的登录回调地址。
- **FR-009**: 部署 MUST 导入与本地相同的测试用户（user1 / engineer1 / admin1，密码同用户名，角色与本地一致），使 e2e 与手动验收可沿用本地账号（负责人 2026-11-10 决定）。
- **FR-010**: Keycloak 管理员凭证 MUST 自动生成随机强密码并存于集群 Secret，MUST NOT 使用默认密码。

**开发环境**

- **FR-011**: 系统 MUST 提供开发模式命令：在开发 namespace 中以开发模式运行 bff 与 web，并把开发机工作区中 bff、web 及其依赖的仓库内公共包的源文件改动持续同步到运行中的进程，改动 MUST 在 10 秒内生效，MUST NOT 需要 git 提交、推送或镜像构建。
- **FR-012**: 开发环境的 bff MUST 连接共享环境的 OpenMetadata、Doris（经 AI 网关与 MCP Toolbox）、Keycloak、Langfuse 与观测组件，MUST NOT 在开发 namespace 重复部署这些组件；开发环境 bff 的自有数据 MUST 使用与共享环境 bff 分开的数据库，二者会话互不干扰。
- **FR-013**: 开发环境 MUST 通过独立的域名以 HTTPS 对外访问；开发环境 MUST NOT 修改共享环境的组件配置或数据，登录回调登记（FR-008）除外。
- **FR-014**: 开发模式命令 MUST 在开发机资源限额内运行（约 1.5 核、2 GB 内存），MUST NOT 在开发机上执行编译、镜像构建或测试。

**集群内检查与测试**

- **FR-015**: 系统 MUST 提供在集群内运行代码检查（对应 `make lint`）、单元 / 契约 / 集成测试与覆盖率（对应 `make test`）、端到端测试（对应 `make e2e`）的命令；检查对象 MUST 是开发机当前工作区（含未提交改动）。
- **FR-016**: 集群内测试的输出 MUST 实时显示在开发机终端，命令退出状态 MUST 与测试结果一致；中断或结束后 MUST 清理为该次运行创建的临时资源。
- **FR-017**: 集群内集成测试 MUST 使用真实依赖（宪法原则 I），MUST NOT 需要开发机上的 Docker。
- **FR-018**: 集群内端到端测试 MUST 针对开发环境运行。

**对外访问与证书**

- **FR-019**: 云端入口 MUST 通过 DigitalOcean 负载均衡器对外提供服务，使用负责人提供的自有域名；仅提供 HTTPS，HTTP 请求 MUST 重定向到 HTTPS；证书 MUST 由公共受信 CA 签发并自动续期。
- **FR-020**: 除织境 Web 与 Keycloak 外，本地 `make ports` 提供的各组件界面（OpenMetadata、Langfuse、Airflow、Jaeger、Prometheus、OpenSearch Dashboards、AI 网关管理界面）MUST 各以织境域名下的子域名经 HTTPS 对公网开放（负责人 2026-11-10 决定）；登录方式沿用组件自身在本地环境的配置。模拟源系统的数据库端口 MUST NOT 对公网开放。
- **FR-021**: 浏览器访问、登录跳转、OpenMetadata 登录回调等所有对外地址 MUST 使用云端域名，MUST NOT 残留 `localhost`、`127.0.0.1.nip.io` 等本地地址；部署输出 MUST 给出负载均衡器的公网地址与所需 DNS 记录。

**镜像构建与分发**

- **FR-022**: 系统 MUST 提供集群内构建 bff 与 web 镜像的命令：基于开发机当前工作区在集群内构建，推送到 DOCR 并更新开发环境，MUST NOT 需要开发机上的 Docker 或 git 推送。集群内 MUST NOT 构建 OpenMetadata 相关镜像。
- **FR-023**: 系统 MUST 提供 GitHub Actions 流水线，构建共享环境使用的全部 5 个自建镜像（bff、web、openmetadata-server、openmetadata-fuseki、openmetadata-ingestion-airflow）并推送到 DOCR，镜像标签 MUST 可追溯到源提交。流水线 MUST 仅由手动触发（可选择分支或提交），推送与合并 MUST NOT 自动触发（负责人 2026-11-10 决定）；对上游版本未变的 OpenMetadata 相关镜像 MUST 复用已存在的镜像；构建凭证 MUST 存于 GitHub 仓库的加密 Secret 中。
- **FR-024**: 集群 MUST 使用只读的镜像拉取凭证从 DOCR 拉取自建镜像；运维者 MUST 能在部署共享环境时指定镜像版本。

**存储、资源与数据**

- **FR-025**: 有状态组件 MUST 使用集群提供的持久块存储；需要共享读写卷的场景 MUST 改为不依赖共享卷的方式。
- **FR-026**: 003 模拟源系统（模拟 MES / QMS）MUST 可按需单独部署到共享环境（对应本地 `make mock-data`），默认部署不包含。
- **FR-027**: 织境的云端工作负载（共享环境、开发环境、集群内构建与测试）MUST 只调度到弹性节点池；各组件资源参数 MUST 有一套云端专用参数，与本地 `local` / `lite` 参数分开维护，使共享环境、开发环境与一次构建或测试任务能同时容纳在弹性池上限（6 × 4 核 8 GB）内。
- **FR-028**: 共享环境部署完成后 MUST 执行与本地相同的组件冒烟测试，并执行 OpenMetadata 本体配置（对应本地部署第 6 步）；任一失败时命令 MUST 以失败状态结束。

**运维**

- **FR-029**: 系统 MUST 提供云端版本的组件信息查看入口（对应本地 `make ports`）与数据初始化入口（对应本地 `make seed`）。
- **FR-030**: 系统 MUST 分别提供开发环境与共享环境的卸载入口，只删除对应 namespace 及其创建的资源，MUST 在删除前要求显式确认，MUST NOT 删除集群中其他 namespace 的资源；卸载开发环境 MUST NOT 影响共享环境。
- **FR-031**: 系统 MUST 提供开发机工具准备脚本，把云端命令所需的轻量命令行工具安装到开发机持久卷上的用户目录（不需要 root 权限，Pod 重建后仍可用），并锁定版本；MUST NOT 安装 Docker 或需要开发机扩容。

**启停**

- **FR-032**: 系统 MUST 提供停止命令：停止织境在弹性池上的全部工作负载（共享环境、开发环境，以及织境安装的集群级控制器与集群内构建 / 测试任务），使弹性池中不再有织境的 Pod，弹性池可释放到其最小节点数；MUST NOT 删除持久卷、Secret 与配置，MUST NOT 影响固定开发节点及其上的 devbox-0。
- **FR-033**: 停止命令 MUST 等待弹性池节点释放到最小节点数后再结束，并输出释放后的节点数；超过等待上限时 MUST 报告阻止释放的资源并以失败状态结束。
- **FR-034**: 系统 MUST 提供启动命令：把停止的环境恢复到停止前的组件、副本数与版本，等待就绪并运行冒烟测试，全部通过后输出访问地址；启动 MUST NOT 重新生成密钥、密码或重新初始化数据。
- **FR-035**: 停止与启动 MUST 可重复执行并能从中途失败中恢复：对已处于目标状态的环境直接报告成功；对部分运行的环境收敛到目标状态。
- **FR-036**: 系统 MUST 提供状态查看命令，显示共享环境与开发环境各自的运行状态（运行中 / 已停止 / 部分运行）与弹性池当前节点数。
- **FR-037**: 停止期间对外访问地址（域名与负载均衡器公网地址）MUST 保持不变，启动后无需修改 DNS；停止期间访问域名时返回明确的不可用响应，而不是长时间无响应。
- **FR-038**: 停止命令在发现集群内测试、镜像构建或开发模式正在运行时 MUST 先提示并要求确认。

### Key Entities

- **云端环境配置**：一份不入库的配置，包含目标集群上下文、共享与开发 namespace、共享与开发环境域名、镜像仓库地址与镜像版本、证书联系邮箱、模型服务配置等。
- **部署环境参数集（云端环境）**：与 `local`、`lite` 并列的组件参数，描述云端域名、入口类型、存储类、节点调度与资源规格。
- **共享环境**：完整织境平台所在的 namespace，镜像来自流水线，供演示、验收及开发环境共用。
- **开发环境**：只运行开发中 bff 与 web 的 namespace，代码来自开发机工作区，依赖共享环境的其余组件。
- **自建镜像版本**：同一提交构建出的一组自建镜像，标签可追溯到源提交；开发环境的集群内构建另有可区分的标签。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在已准备好凭证与 DNS 的开发机上，共享环境首次部署到全部冒烟测试通过不超过 60 分钟（含节点扩容与镜像拉取），重复部署不超过 20 分钟。
- **SC-002**: 开发模式运行中，开发者保存 bff 或 web 源文件后 10 秒内在开发环境中看到改动；从执行开发模式启动命令到可在浏览器访问开发环境不超过 5 分钟。
- **SC-003**: 开发者在开发机上完成“改代码 → 集群内跑测试 → 浏览器查看”的一轮，全程无需 git 提交或推送，开发机内存占用不超出其 2 GB 限额。
- **SC-004**: 集群内的代码检查与单元 / 契约测试在 10 分钟内给出结果；bff 或 web 的集群内镜像构建并更新开发环境在 10 分钟内完成。
- **SC-005**: 团队成员可在任意联网电脑的浏览器中，通过共享环境域名在 1 分钟内完成登录并进入首页，浏览器不出现证书警告。
- **SC-006**: 连续执行 3 次共享环境部署后，已有业务配置与数据（已接入的数据源、OpenMetadata 元数据、Langfuse 轨迹）100% 保留，所有用户可用原凭证登录。
- **SC-007**: 云端能力引入后，本地 kind 部署（`make up`、`make up ENV=lite`）的执行结果与引入前一致，现有自动化测试全部通过。
- **SC-008**: 手动触发流水线后 60 分钟内，该提交的全部自建镜像可在镜像仓库中获取（OpenMetadata 相关镜像版本未变时 15 分钟内）。
- **SC-009**: 卸载开发环境后共享环境仍可正常登录使用；卸载共享环境后，集群其他 namespace 的资源数量与卸载前一致。
- **SC-010**: 仓库、镜像与流水线日志中不出现任何明文凭证（由密钥扫描验证）。
- **SC-011**: 执行停止命令后 20 分钟内，弹性池节点数降到最小节点数，devbox-0 全程可用。
- **SC-012**: 执行启动命令后 30 分钟内，共享环境与开发环境恢复运行并通过冒烟测试；停止再启动后，停止前的业务数据与配置 100% 保留，访问域名不变。

## Assumptions

- 目标集群为开发机 devbox-0 所在的 DOKS 集群（负责人 2026-11-10 确认）。弹性节点池单节点 4 核 8 GB，最大节点数已由负责人调整为 6；按 local 参数估算，共享环境资源保证值约 15 GB 内存，6 个节点扣除系统预留后约 33 GB 可用，可同时容纳共享环境、开发环境与一次构建或测试任务。集群的创建、版本升级与节点池配置不在本特性范围内。
- 运维者可获得对该集群有足够权限的 kubeconfig（能创建 namespace、CRD、LoadBalancer 以及在弹性池上运行构建与测试 Pod）。
- 开发机 devbox-0 不扩容（约 1.5 核、2 GB 内存）、不安装 Docker（负责人 2026-11-10 决定）；开发机与集群内服务网络互通。开发机目前也没有 kubectl、helm、helmfile、doctl、python3、uv、pnpm、node，由 FR-031 的准备脚本安装其中云端命令所需的工具；需要较多资源的工具链（Python 与前端依赖安装、类型检查、测试）在集群内运行。
- 集群内运行集成测试所需的真实依赖的提供方式（集群内临时容器运行环境，或连接共享环境的真实组件），以及集群内镜像构建与文件同步采用的具体工具，在 plan 阶段调研集群条件（如是否允许特权容器）后确定。
- 开发环境与共享环境共用 OpenMetadata、Doris、Langfuse 等组件中的数据：在开发环境中的操作（如接入数据源、触发采集）会反映到共享环境，负责人知情接受（2026-11-10 决定开发环境共用这些组件）。
- 负责人拥有自有域名并能在域名服务商处添加 DNS 记录；证书默认采用 HTTP 校验方式签发（不要求域名托管在 DigitalOcean）。具体域名作为配置项提供，不写入仓库。
- 负责人已开通或可开通 DOCR，并能为集群生成镜像拉取 / 推送凭证、为 GitHub 仓库生成推送令牌。
- 开源组件镜像（自建镜像之外的上游镜像）由集群节点从公网镜像仓库直接拉取。
- 云端环境为 Phase 1 单租户的开发 / 测试 / 演示环境，租户常量沿用本地设置；不承载客户生产数据，不存放客户三级数据。
- 宪法“部署约束”一节以阿里云 ACK / ACR 作为自有测试环境，并要求测试环境由流水线基于已合并的提交部署；本特性在 DOKS 上新增开发与测试环境、共享环境镜像可由任意分支手动触发构建，属于偏离，须在 plan 的 Constitution Check 中记录理由，必要时修订宪法。
- **已知风险（负责人 2026-11-10 知情决定）**：测试用户密码同用户名；Jaeger、Prometheus、OpenSearch Dashboards、AI 网关管理界面在本地环境本身没有登录保护。公网开放后，任何知道域名的人都可以访问这些界面或登录织境（共享环境与开发环境）。因此云端环境只能存放模拟数据，MUST NOT 接入任何真实数据或客户数据；该风险须写入 `acceptance.md` 的已知限制。
- devbox-0 运行在独立的固定开发节点（池）上，不在弹性池中；弹性池最小节点数已设为 0，自动扩缩由 DOKS 完成（负责人 2026-11-10 确认）。plan 阶段仍须实测弹性池确能缩到 0；若不能，停止后保留最小节点数，命令如实报告。
- 停止期间仍会产生少量费用：持久卷（块存储）、负载均衡器（为保持访问地址不变而保留，负责人 2026-11-10 确认）与 DOCR 存储；本特性只释放弹性池节点。停止期间 Airflow 定时采集不执行、启动后不补跑（负责人 2026-11-10 确认）。
- 模型服务（AI 网关的模型路由）沿用本地的配置方式，由负责人在云端配置文件中提供。
