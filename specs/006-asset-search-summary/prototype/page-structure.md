## 2. 目标形态：一个「数据资产」页面

做法是把 OM Explore 的交互搬到织境「数据资产」页，005 原来的目录树改成 Explore 的浏览树。浏览、搜索、筛选、摘要都在这一个页面完成；数据源管理和资产详情作为同一页面下的子视图。

### 2.2 各区域与 OM 的对应

| 区域 | 织境做法 | 对应的 OM 行为 | 数据来源 |
| --- | --- | --- | --- |
| 搜索框 | 放在数据资产页顶栏；输入防抖，建议按类型分组，每类最多 5 条，点建议直接进详情；回车后按相关性排序 | GlobalSearchBar、Suggestions | `/search/query`（2.0.3 没有 suggest 接口） |
| 浏览树 | 替换 005 目录树，层级「服务类型 → 服务 → 库 → Schema → 实体类型」，带计数，展开时懒加载，计数为 0 的根不显示；**点击节点只设置位置条件，不跳页** | ExploreTree、browsePath | `/search/aggregate` 加 `/search/query` 的聚合 |
| 类型列表 | 有关键词时，左栏换成计数大于 0 的类型；默认选首条命中结果的类型，否则选计数最多的类型 | 类型 Menu、默认 tab 规则 | `/search/entityTypeCounts` |
| 快速筛选 | 维度清单按 OM：不分类型时是资产类型、域、数据产品、所有者、标签、Tier、服务、服务类型、认证；表类型额外有库、Schema、列、表类型、列描述。同一维度内为 OR，跨维度为 AND，可以选「无」；选项计数排除本维度自身的条件 | ExploreQuickFilters | `/search/aggregate` |
| 条件条 | 位置条件逐层显示，删除某层连同下层一起删；筛选值单独可删；「清除全部」；无关键词且没有条件时显示提示文案 | ExploreQueryFilterChips | — |
| 排序与分页 | 热度（默认）、名称、相关性、更新时间，降序；改排序回到第 1 页；每页 15 / 25 / 50 条 | SortingDropDown、分页组件 | `/search/query` |
| 结果卡片 | 面包屑、图标和名称、认证徽章、描述（高亮）、域、所有者、Tier、命中字段统计 | ExploreSearchCard | `/search/query` 的 `_source` 和 `highlight` |
| 摘要面板 | 结果更新后自动选中第一条，无结果时关闭；**只读**；页签先做「概览」和「Schema」；标题链接到实体详情 | EntitySummaryPanel | 实体接口（复用 005 的 `/bff/v1/catalog/{type}/{fqn}` 或扩展它） |

### 2.4 页面状态

原型要覆盖以下状态。状态种类按宪法要求，示例数值只用在原型里。

1. 首次进入，无关键词：显示浏览树、全部资产和提示文案。
2. 有关键词：左栏是类型列表，有结果、有高亮。
3. 有筛选条件：显示条件条，同一维度多选。
4. 无结果：显示空状态，摘要面板关闭。
5. 加载中：显示骨架或加载提示。
6. 出错：OM 不可用、索引缺失时显示真实的错误码和重试入口，**不退回示例数据**。
7. 还没有任何资产：引导去「添加数据源」，或说明可以用开发态导入。
8. 窄屏：浏览树收进「目录」抽屉（沿用 005 的做法）。
9. 带完整 URL 刷新后，所有条件都恢复。
