## 界面与交互基线（对齐 OM Explore 与页面结构方案）

1. **统一页面**：一级导航「资产」进入 `/assets`。浏览、搜索、筛选、摘要都在这一页完成。以下作为同页面子视图，与探索视图共用左侧二级栏：
   - 005 的数据源管理与资产详情；
   - 006 新增的业务术语、分类标签只读详情。
2. **左侧二级栏**：沿用当前生产外壳的可拖宽二级栏，以及窄屏下的「目录」抽屉。不再显示「资产搜索」「数据源」两个链接（D2）。
   - 无关键词时显示**浏览树**：由 005 的四层目录树改造而来。根节点按 OM 资产大类分组（如数据库、治理）；数据库类按「服务类型 → 服务 → 库 → Schema → 实体类型」逐层展开，每个节点显示计数，展开时才加载下层，计数为 0 的根节点不显示。点击节点只设置位置条件，不跳页。
   - 有关键词时左栏换成**类型列表**，只列命中计数大于 0 的资产类型并显示计数。
3. **顶栏**：左侧是面包屑，右侧是账户。中间是本页的搜索框（D3），带搜索范围选择（D4，选项只列有数据的类型），以及输入防抖的建议浮层。
4. **页头**：标题、结果数量，以及「数据源管理」「添加数据源」两个入口。
5. **工具区**：快速筛选下拉、排序（字段 + 升降序），以及条件条（位置条件、筛选值、清除全部）。
6. **主体**：左边是结果卡片列表与分页，右边是只读摘要面板（页签为「概览」「Schema」）。

## User Scenarios & Testing *(mandatory)*

> 各故事的独立测试使用开发态导入工具（FR-016）写入 OM 的测试元数据，也可以同时使用 005 实际采集的资产。

### User Story 1 - 用关键词搜索资产并查看摘要 (Priority: P1)

数据处理与治理人员在「数据资产」页顶栏输入中文业务名、英文表名、字段名或描述中的词。输入过程中先看到按类型分组的建议，可以直接点建议进入资产；回车后看到按相关性排序的结果。左栏换成按类型计数的列表。结果卡片里，命中的词会高亮，并标明资产来自「真实采集来源」还是「开发态测试元数据」。系统自动选中第一条结果，并在右侧显示它的摘要（描述、负责人、业务域、分级、数据安全级别、认证、业务术语、分类标签、数据产品，以及表的字段清单）。

**Why this priority**：这是 006 的核心价值，也是 Phase 1「006 资产业务演示」的主路径：登录 → 搜索 / 筛选 OM 资产 → 选择资产 → 查看摘要与字段。

**Independent Test**：导入测试元数据后，在 `/assets` 按表名、字段名、描述中的词搜索，核对结果、类型计数、高亮、来源标识与摘要内容都与 OM 中的实体一致。

**Acceptance Scenarios**:

1. **Given** OM 中已有表资产，**When** 用户在搜索框输入关键词并停顿，**Then** 显示建议浮层：按资产类型分组，每类最多 5 条；点击某条建议直接进入该资产的详情（进入方式见 FR-012）。
2. **Given** 用户输入关键词后回车，**When** 结果返回，**Then**：
   - 列表按相关性排序，页头显示结果总数；
   - 左栏换成计数大于 0 的类型列表，默认选中首条命中结果的类型，没有首条时选计数最多的类型；
   - 卡片的名称和描述中，命中的词高亮显示。
3. **Given** 结果列表已经更新，**When** 列表非空，**Then** 自动选中第一条并显示其摘要；用户点击其他卡片后，摘要切换为该资产；按 Esc 或点关闭按钮可以关闭摘要。
4. **Given** 选中的是一张表，**When** 用户切到摘要的「Schema」页签，**Then** 列出该表全部字段：名称、数据类型、主键或唯一约束标识、描述、分类标签（含数据级别标签）。
5. **Given** 用户在搜索框选择了某个搜索范围（如只搜表），**When** 执行搜索，**Then** 结果只包含该类型的资产。
6. **Given** 结果中同时有开发态导入的资产和 005 采集的资产，**When** 用户查看卡片与摘要，**Then** 两类资产能被区分开，开发态测试元数据不会表现为已连通的源库。
7. **Given** 关键词没有任何命中，**When** 搜索完成，**Then** 显示「无匹配结果」空状态和清除条件入口，摘要面板关闭。

### User Story 2 - 把 005 目录树改造为可筛选的浏览树，并用快速筛选组合定位资产 (Priority: P1)

**与 005 的关系**：005 已有四层目录树（服务 → 库 → Schema → 表），只在数据源页面显示，点击节点会跳到资产详情页，计数来自逐层的实体统计。006 对它做两件事：

- **改造**：目录树成为数据资产页的浏览树。层级改为「服务类型 → 服务 → 库 → Schema → 实体类型」，并增加治理类根节点；计数改用 OM 搜索聚合；点击节点不再跳页，只设置位置条件。展开 / 收起和窄屏抽屉沿用 005 的做法。
- **新增**：005 没有的跨服务资产结果列表、快速筛选、条件条、排序与分页。

用户不输入关键词，从左侧浏览树逐层展开到某个服务、库或 Schema，点击后列表只保留该位置下的资产，页面不跳转。再用快速筛选（资产类型、业务域、数据产品、负责人、分类标签、分级、服务、服务类型、认证，选中表类型时再加库、Schema、列、表类型、列描述）组合缩小范围，也可以选「无」找出缺少负责人、缺少分级等属性的资产。条件条列出所有生效条件，每个条件可以单独删除，也可以一次清除全部。结果可以按热度、名称、相关性、最近更新排序，并分页浏览。

**Why this priority**：落实 005 关闭时「同页浏览、与 OM 一致」的遗留决定；发现缺失属性的资产是治理人员的日常工作。

**Independent Test**：在导入的测试元数据上，分别执行：点击树节点、多选同一维度、跨维度组合、选择「无」、逐层删除位置条件、清除全部、切换排序、切换每页条数、翻页。核对结果数量与 OM 搜索聚合的计数一致。

**Acceptance Scenarios**:

1. **Given** 搜索框为空，**When** 用户进入 `/assets`，**Then** 左栏显示带计数的浏览树，列表显示全部资产，条件条显示操作提示文案。
2. **Given** 用户点击浏览树中某个 Schema 节点，**When** 列表刷新，**Then**：
   - 列表只含该 Schema 下的资产；
   - 条件条从上到下逐层显示位置（大类、服务类型、服务、库、Schema）；
   - 页面不跳转。

   删除其中某一层时，这一层及其下层位置条件一并删除。
3. **Given** 用户在同一个筛选维度勾选两个值，再在另一个维度勾选一个值，**When** 列表刷新，**Then** 结果满足「（值 1 或 值 2）且 值 3」。每个下拉选项旁的计数不受本维度自身已选条件的影响。
4. **Given** 用户在「负责人」或「分级（Tier）」维度选择「无」，**When** 列表刷新，**Then** 只显示没有设置该属性的资产。
5. **Given** 已有关键词、位置与筛选条件，**When** 用户点「清除全部」，**Then** 关键词、位置和筛选全部清空，回到无关键词的浏览状态。
6. **Given** 结果超过一页，**When** 用户切换排序字段或升降序，**Then** 回到第 1 页并按新顺序展示。每页条数可选 15 / 25 / 50，翻页结果与总数一致。
7. **Given** 存在位于不同服务或 Schema 下的同名表，**When** 用户按表名搜索，**Then** 每条结果都显示完整位置面包屑，能据此区分。

### User Story 3 - 在同一页面使用数据源管理与各类资产详情 (Priority: P2)

用户从页头的「数据源管理」「添加数据源」进入 005 的数据源列表、接入向导、采集任务与采集配置。从卡片名称、摘要标题或建议进入资产详情：

- 库、Schema、表：进入 005 的详情页，并继续在那里编辑属性；
- 业务术语、分类标签：进入 006 新增的只读详情页。

这些子视图都在 `/assets` 下，共用左侧浏览树。在子视图里点击浏览树会回到探索视图，并带上对应的位置条件。旧的 `/sources/...` 地址自动转到新地址（D1）。

**Why this priority**：统一页面会改动 005 已验收的入口和路径，必须保证 005 功能不退化、旧链接可用；但它依赖 US1 和 US2 的探索视图先成立。

**Independent Test**：
- 按 005 `acceptance.md` 的主要步骤在新路径下重走一遍；
- 打开若干旧 `/sources/...` 链接，核对都能转到对应的新页面；
- 从搜索结果进入一个业务术语和一个分类标签的详情，核对内容与 OM 一致。

**Acceptance Scenarios**:

1. **Given** 用户在探索视图，**When** 点击页头「数据源管理」或「添加数据源」，**Then** 进入 005 的数据源列表或接入向导，功能与 005 验收时一致。
2. **Given** 用户点击某张表卡片的名称或摘要标题，**When** 页面切换，**Then** 进入该表的详情（005 的结构信息、字段与属性编辑）；在本次会话内返回探索视图时，原有的关键词、位置、筛选、排序与页码保持不变。
3. **Given** 用户点击某个业务术语或分类标签结果的名称，**When** 页面切换，**Then** 进入该术语或标签的只读详情页：内容取自 OM 实体，页面上没有编辑入口，并可以返回探索视图。
4. **Given** 用户位于任一子视图，**When** 点击左侧浏览树的某个节点，**Then** 回到探索视图，并以该节点作为位置条件。
5. **Given** 用户打开旧地址 `/sources` 或 `/sources/{服务}/assets/{类型}/{fqn}`，**When** 页面加载，**Then** 自动转到 `/assets` 下对应的数据源管理或资产详情页面。

### Edge Cases

- **加载中**：搜索、计数、浏览树、筛选项、摘要与详情在请求过程中显示加载状态，不先显示旧结果或示例。
- **检索服务出错**：OM 搜索不可用、超时或索引缺失时，在结果区显示真实的错误码与说明，并提供重试入口。不回退内置示例数据，不显示伪造的空结果或成功结果。
- **平台上还没有任何资产**：显示零资产空状态，引导用户去「添加数据源」，并说明可以用开发态导入。浏览树不显示计数为 0 的根节点。
- **写入后短暂搜不到**：OM 写索引失败会进入重试队列，用户级缓存也可能让新写入的资产短暂不可见。界面如实显示当前搜索结果，不自行补齐；验收中记录观察结果。
- **同名资产**：不同服务、库或 Schema 下的同名表，卡片面包屑与摘要都显示完整位置（FQN）；列表与摘要使用同一实体身份（类型、ID、FQN），选中、切换时不串号。
- **列结果混入**：OM 的数据资产集合包含列级文档。列只在类型列表中作为独立的「列」类型出现（D8），不混进表的计数和表的结果。
- **结果窗口上限**：OM 单次结果窗口最多 10000 条。超出时分页不越界，并提示用户缩小条件。
- **查询语法字符**：关键词中的特殊符号或大写 AND / OR / NOT，不得导致请求出错或筛选被静默忽略。筛选条件由服务端按结构化参数生成并校验，浏览器不提交原始查询语句。
- **刷新页面**：006 不把搜索条件写入页面地址。刷新或重新打开 `/assets` 时，回到无关键词的初始浏览状态，这是预期行为。
- **权限范围**：OM 默认不按用户权限过滤搜索结果。Phase 1 按宪法例外不做数据层授权，所有登录用户看到同一范围的资产，这一点写进验收说明。
- **中文检索**：当前索引使用 EN 映射，没有中文分词插件。中文关键词的命中和排序效果以验收实测为准（D10），界面不另做本地匹配来弥补。
- **术语或标签已删除**：从结果进入的术语或标签在 OM 中已不存在时，详情页显示真实的「未找到」错误，不显示旧内容。
- **窄屏**：视口不超过 850px 时，浏览树收进顶栏的「目录」抽屉；摘要面板以覆盖层显示。页面在 1280px、768px、390px 宽度下都没有整页横向溢出。

## Requirements *(mandatory)*

### Functional Requirements

**统一页面与导航**

- **FR-001（统一的数据资产页面）**：系统 MUST 在 `/assets` 提供统一的「数据资产」页面，在同一页完成浏览、搜索、快速筛选、条件条、排序分页、结果卡片与只读摘要；`/assets` MUST NOT 再显示「尚未开放」占位页。
- **FR-002（子视图与路由）**：
  - 系统 MUST 把 005 的数据源管理（列表、接入向导、采集任务、采集配置）放到 `/assets/sources/...` 下；
  - 系统 MUST 把库、Schema、表详情（含属性编辑）以及 006 新增的业务术语、分类标签只读详情，放到 `/assets/{类型}/{fqn}` 下；
  - 005 的功能 MUST 与验收时一致；
  - 旧的 `/sources/...` 地址 MUST 转到对应的新地址（D1）。
- **FR-003（二级栏）**：二级栏 MUST 去掉「资产搜索」「数据源」两个链接，只承载浏览树或类型列表（D2）。二级栏 MUST 保留现有的拖宽能力和窄屏「目录」抽屉；在子视图中点击浏览树节点 MUST 回到探索视图并带上对应的位置条件。

**搜索框与建议**

- **FR-004（搜索框与范围）**：数据资产页顶栏 MUST 提供搜索框（D3），左侧带搜索范围下拉（D4），选项只列当前有数据的资产类型。下拉默认不选择任何类型，此时搜索全部资产；选择某个类型后只搜该类型。回车执行搜索时，排序 MUST 默认改为相关性。
- **FR-005（输入建议）**：输入停顿后 MUST 显示按资产类型分组的建议，每类最多 5 条，每条显示名称与位置。点击建议 MUST 直接进入该资产（进入方式见 FR-012）。建议使用与主搜索相同的 OM 搜索能力，因为 OM 2.0.3 没有专门的建议接口。

**左栏：浏览树与类型列表**

- **FR-006（浏览树，改造 005 目录树）**：无关键词时，左栏 MUST 显示由 005 四层目录树改造而来的浏览树：
  - 根节点按 OM 资产大类分组；数据库类按「服务类型 → 服务 → 库 → Schema → 实体类型」逐层展开；
  - 计数改用 OM 搜索聚合的结果；子层展开时才加载；计数为 0 的根节点不显示；
  - 点击节点 MUST 只设置位置条件、不跳页（005 原来是跳到资产详情页）；
  - 展开 / 收起和窄屏抽屉沿用 005 的行为。
- **FR-007（类型列表）**：有关键词时，左栏 MUST 显示命中计数大于 0 的资产类型及计数，计数取 OM 的按类型计数。默认选中首条命中结果的类型，否则选计数最多的类型；切换类型 MUST 只刷新列表。列（tableColumn）作为独立类型出现（D8）。

**快速筛选、条件条、排序与分页**

- **FR-008（快速筛选）**：系统 MUST 提供与 OM 一致的快速筛选维度。
  - 不分类型时：资产类型、业务域、数据产品、负责人、分类标签、分级（Tier）、服务、服务类型、认证；
  - 选中表类型时额外提供：库、Schema、列、表类型、列描述。

  规则如下：
  - 每个下拉 MUST 支持在选项中搜索，并显示选项计数；计数 MUST 排除本维度自身的已选条件。
  - 同一维度多选 MUST 按「或」组合，跨维度 MUST 按「且」组合，并与关键词、位置条件按「且」叠加。
  - 负责人、业务域、分级、分类标签、认证 MUST 支持选择「无」，用来筛出没有该属性的资产。
- **FR-009（条件条）**：条件条 MUST 按层级显示位置条件（删除某一层时连同下层一起删除）和每个筛选值（可单独删除），并提供「清除全部」。无关键词且没有任何条件时，MUST 显示操作提示文案。
- **FR-010（排序与分页）**：排序 MUST 提供热度（默认）、名称、相关性、最近更新，并可切换升降序（默认降序）；改变排序 MUST 回到第 1 页。分页 MUST 支持每页 15 / 25 / 50 条，页头 MUST 显示真实的结果总数。

**结果卡片、摘要与详情**

- **FR-011（结果卡片）**：每张卡片 MUST 显示：
  - 位置面包屑（服务 / 库 / Schema）、资产类型图标与名称（名称可进入资产）；
  - 认证徽章（有认证时）；
  - 描述，命中词高亮；
  - 业务域、负责人、分级（Tier）、数据安全级别；
  - 命中字段统计；
  - 来源标识，区分「真实采集来源」与「开发态测试元数据」。

  卡片中的数据 MUST 全部来自 OM 的搜索结果。
- **FR-012（摘要面板与进入详情）**：
  - 选中行为：结果更新后 MUST 自动选中第一条；无结果时关闭。用户可以点选其他卡片，也可以按 Esc 或关闭按钮关闭。
  - 内容：摘要 MUST 只读，页签为「概览」「Schema」（D6）。
    - 「概览」依次显示描述、负责人、业务域、分级（Tier）、数据安全级别、认证、业务术语、分类标签、数据产品与来源；
    - 「Schema」列出表的字段（名称、类型、主键或唯一约束、描述、分类标签）。
  - 数据来源：摘要数据 MUST 按选中资产的身份（类型、ID、FQN）从 OM 实体读取，与列表共享同一身份。
  - 进入详情（卡片名称、摘要标题、输入建议）：
    - 库、Schema、表 → 005 的资产详情；
    - 业务术语、分类标签 → FR-013 的只读详情页；
    - 列 → 所属表的 005 资产详情，并定位到该列（Q3）；
    - 其他没有详情页的类型 → 名称不是链接，只选中并显示摘要；点击这类输入建议时，以其名称执行搜索（U1）。
- **FR-013（业务术语与分类标签只读详情页）**：系统 MUST 为业务术语和分类标签提供只读详情页：
  - 内容 MUST 取自 OM 对应实体的原生字段，具体字段清单在 plan 阶段按 OM 2.0.3 实体定义确定，不自行增设字段；
  - 页面 MUST NOT 提供编辑入口；
  - 页面 MUST 提供返回探索视图的入口；
  - 实体不存在时 MUST 显示真实的「未找到」错误。

  该页面在实现前 MUST 先补充到 HTML 原型并经负责人确认（宪法「界面设计先行」）。
- **FR-014（Tier、数据安全级别与认证分开展示）**：卡片、摘要与详情 MUST 把三者分开显示（D7）：
  - 分级（Tier）取 OM 的 `Tier.` 分类标签，显示文案为「分级（Tier）」，与 OM 中文界面一致；
  - 数据安全级别取 OM 分类「数据级别」下的标签（一级 / 二级 / 三级，ADR-0008），单独一行展示，不与其他分类标签混排；
  - 认证取 OM 的认证字段，以徽章展示。

  006 不为数据安全级别单独增加快速筛选维度，沿用「分类标签」维度筛选。

**状态与错误**

- **FR-015（页面状态）**：页面 MUST 覆盖以下状态：
  - 首次进入、无关键词；
  - 有关键词；
  - 有筛选条件；
  - 无结果；
  - 加载中；
  - 出错（真实错误码与重试入口）；
  - 零资产；
  - 窄屏抽屉。

  任何状态下 MUST NOT 显示内置示例数据或伪造的成功结果。在本次会话内从子视图返回探索视图时，MUST 保留原有的搜索条件；搜索条件不写入页面地址。

**测试数据与验收支撑**

- **FR-016（开发态元数据导入工具）**：系统 MUST 提供一个无界面的开发工具，供 US1–US3 独立验收：
  - 从 003 模拟工厂的表定义生成测试元数据，经 OM 正式接口写入服务、库、Schema、表与字段（含中文说明）；
  - 补充少量业务术语、负责人、业务域与分类标签样例，样例 MUST 覆盖同名表、缺失属性与组合筛选；
  - 导入 MUST 幂等：重复运行不产生重复资产，工具输出新建、更新、未变化的数量；
  - 导入的资产 MUST 在写入后能被搜到和浏览。
- **FR-017（导入工具边界）**：导入工具：
  - MUST 只管理自己创建的测试资产，不修改其他资产（包括 005 采集的资产），并可以撤除自己导入的测试资产；
  - MUST NOT 保存凭证；
  - 未显式指定开发态目标环境时 MUST 拒绝写入并提示原因；
  - 导入的资产 MUST 能被识别为「开发态测试元数据」，不得表现为已连通的源库；
  - 工具和测试数据放在 `testdata/`，与 003 一致，不进入客户交付物。

**后端与安全边界**

- **FR-018（优先复用 OM 搜索能力）**：主列表、类型计数、筛选项与浏览树计数 MUST 分别使用 OM 的主搜索、按类型计数和聚合能力；相关性 MUST 使用 OM 默认的搜索设置（验收后如需调整，通过 OM 搜索设置完成）。系统 MUST NOT 自建索引、搜索服务或打分逻辑。
- **FR-019（服务端构造与校验条件）**：浏览器 MUST 只把结构化条件（关键词、范围、类型、位置、筛选、排序、分页）发给织境 BFF，由 BFF 生成并校验 OM 查询条件；不合法的条件 MUST 返回明确错误，MUST NOT 被静默忽略。浏览器 MUST NOT 直连 OM 或 OpenSearch。
- **FR-020（身份与审计）**：BFF 调用 OM 时 MUST 沿用 005 的用户委托令牌；搜索、摘要与详情请求 MUST 输出带 `trace_id` 与 `tenant_id` 的结构化日志。Phase 1 不做数据层授权（宪法 IV 例外），搜索结果范围与 OM 当前设置一致，并写入验收说明。

### Key Entities *(include if feature involves data)*

按宪法原则 VII，本特性**不新增任何持久化实体或数据表**，全部复用 OpenMetadata 2.0.3 的实体与搜索索引。下列只是界面与接口使用的数据形态（DTO 或投影），持久化事实都在 OM。

- **类型计数 / 筛选项 / 浏览树节点**：从 OM 按类型计数与聚合结果投影得到，包括取值、显示名与计数。
- **资产摘要 / 术语与标签详情**：按身份从 OM 实体读取的只读视图。
- **开发态测试资产标识**：区分「开发态测试元数据」与真实采集资产的标记。它承载在 OM 原生字段上（具体方式由 plan 选定），不新增实体。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001（可搜到、可浏览）**：开发态导入完成后，100% 导入的表都能按英文表名搜到，并能在浏览树对应的服务 / 库 / Schema 节点下找到；浏览树、类型列表和筛选项的计数与 OM 中的实际资产数一致。
- **SC-002（主路径效率）**：用户从打开 `/assets` 到看到目标表的摘要与字段，通过搜索或浏览树都能在 30 秒内、5 次操作以内完成。

## Assumptions

- **前置依赖**：003（表定义）与 004（Web 外壳）已完成；005 已验收关闭（2026-11-08），其采集结果可以同时用于浏览验证，但 006 的验收不强制依赖 005。
- **环境前置**：本地 OpenSearch 在 2026-11-09 核查时已重启 286 次，开发 006 前先排查（D11）。如果环境问题未解决，相关验收项按「环境阻塞」如实写进 `acceptance.md`，不以假实现代替。
- **OM 能力边界**：OM 写入实体后同步写搜索索引，写完立即可搜；失败时进入重试队列。OM 2.0.3 没有建议接口；结果窗口上限 10000；查询超时 30 秒。以上均以调研文档的源码出处为准。
- **访问角色**：数据资产页（含搜索、摘要、详情）沿用织境 Web 现有的访问控制：只有 `admin` 或 `ai-engineer` 角色可以访问（BFF `require_web_context`）。006 不新增角色。
- **权限**：OM 搜索设置保持默认（不按用户权限过滤），与宪法 IV 的 Phase 1 例外一致；以后开启时调用方式不变。
- **中文检索**：006 不修改 OM 的索引语言映射，也不安装分词插件（D10）。
