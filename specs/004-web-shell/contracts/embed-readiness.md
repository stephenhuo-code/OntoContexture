## 输出和门禁

报告置于本特性的 research.md 或其链接的证据附件，每项必须记录真实输入与结果，失败与未执行单列。

- 004 产品依赖调整前先完成真实构建与挂载实测；失败需先确定解决路径，不能按“以后会兼容”开始外壳代码重构。
- 没有依赖 / 构建环境时静态研究可完成规划，但 SC-007 与 004 手动验收仍未通过；后续 tasks 必须把实测排在受影响实现之前。
- 004 不要求完整 Omnigent 服务部署与真实 Agent 对话；007 的身份、代理、共享会话、上游执行禁用必须另验。
- 不能将浏览器 X-Forwarded-Email 等头直接转发作授权；BFF 需剥离未受信头并使用符合签名身份要求的桥接方案。
- SidebarConfig 已查到只控制轮询 / sharing / 分页等，**没有通用隐藏终端 / 执行能力的开关**；不得以该参数或 CSS 隐藏代替服务端限制。
- 上游 host config / QueryClient / 身份缓存含模块级状态，007 必须验证侧栏和整页共享会话的生命周期，不能默认两实例天然一致。
- 如官方扩展不满足签名身份或能力关闭要求，007 单独按宪法 VI 评估扩展 / 上游提议 / 最小补丁；004 不复制源码规避。
- 两个节点各自记录“通过 / 失败 / 未执行”、实际输入、可复现命令、证据与责任特性；004 的实测见上述证据；007 项全部仍为 not_run。
