## 一句话

交付一个可以独立登录、导航和退出的织境 Web 外壳，让数据处理与治理人员使用统一的入口、页面布局和账号操作，
让后续特性直接接入统一布局和公共组件；本次不以资产搜索、Agent 对话、审批处理或终端可用作为验收条件。

## Clarifications

### Session 2026-10-31

- Q: 点击退出织境时，是否影响 Paperclip 的登录状态？ → A: Paperclip 的登录状态与织境无关；004 只处理和验收织境自己的会话退出，不联动 Paperclip，不以其登录状态判断织境退出结果。
- Q: 哪些角色可以进入织境 Web 外壳？ → A: 只有管理员（admin）或 AI 工程师（ai-engineer）可进入；仅有业务用户（business-user）角色或不具备任一准入角色的已认证用户显示无权限。兼有业务用户与任一准入角色时可进入。

### Session 2026-11-02

- Q: 退出织境是否调用 IdP logout？ → A: 不调用。只删除当前织境 BFF 会话及其中保存的令牌、过期会话 Cookie，并清理前端用户与业务缓存；不结束企业 SSO、不联动其他客户端。成功后停留匿名登录入口；用户主动再次登录时，已有企业 SSO 可以建立新的织境会话。

### Session 2026-11-03

- Q: 退出后再次登录是否允许已有 SSO 直接进入？ → A: 不允许。首次登录、退出后登录和失败页重新登录统一要求 Keycloak 重新认证，BFF 固定携带 prompt=login；当前本地密码认证需要输入密码。有效织境会话的刷新、切页与令牌续期不触发重新认证。退出仍只结束织境会话，不调用 IdP logout、不主动注销其他客户端。本决定替代上一日“主动登录可直接复用 SSO”的交互规则，保留应用内退出边界。

### Session 2026-11-03：用户验收职责

- Q: 用户是否需要到开发组件演示页检查按钮变体、模拟故障和页面接入？ → A: 不需要。用户只在正式入口验收真实页面的登录退出、账号、导航、布局和建设状态。基础组件、故障模拟、开发示例、页面接入、兼容性与旧示例回归由开发侧执行并交付验证证据，不作为用户手动操作步骤；这些工程交付和质量门禁仍保留。

### Session 2026-11-03：登录视觉确认

- Q: 登录页采用什么视觉方案？ → A: 采用用户提供浅蓝参考后确认的提案 B：白色品牌页头、浅冰蓝主视觉、深色文字、亮蓝按钮、白色登录卡片及产品价值区。登录入口与企业认证页视觉统一。确认依据为 [登录原型](prototype/login/index.html)，SHA-256 `f8c27d3a95622a66cf78ae2c30b7d19ac6833a0f4c7efe3f4dc108a2b0bdeb56`；原型仅为设计输入，不复用为生产代码。企业密码仍只提交身份服务，退出与重新认证规则保持。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录织境、进入首页并查看当前账号 (Priority: P1)

作为具有管理员或 AI 工程师角色的数据处理与治理人员，我希望用已有企业账号进入织境首页，查看当前账号并能退出，
以便在明确身份的情况下开始工作。004 将 001 已有的登录与会话接入新外壳，不重新建设身份功能。

**Why this priority**: 后续所有页面都依赖可信的会话与一致的账号体验，004 不应另做一套登录。

**Independent Test**: 使用一个有效账号完成进入首页、查看身份、退出、重新访问的完整过程；不需要搜索、Agent 或审批服务。

**Acceptance Scenarios**:

1. **Given** 没有有效会话，**When** 打开织境或站内受保护页面，**Then** 进入已有企业登录流程；织境不提供新的密码输入页。
2. **Given** 完成企业认证，**When** 返回织境，**Then** 显示外壳与当前用户；首次进入默认首页概览，
   从有效站内目标进入则回到该目标，缺失或不安全的返回目标回到首页。
3. **Given** 已登录，**When** 查看账号入口，**Then** 显示真实姓名或账号名；仅在身份中有可用角色时展示角色，
   不写死原型中的 engineer1 或“AI 工程师”。账号名缺失时使用可识别的用户标识。
4. **Given** 已登录，**When** 退出完成后刷新或再次进入站内受保护页面，**Then** 原织境会话不能继续访问，
   必须重新建立有效的织境会话；浏览器返回上一页时不能继续操作原用户页面。Paperclip 的登录状态不参与本项验收。
5. **Given** 会话过期或失效，**When** 加载页面，**Then** 清除当前用户的已登录展示并提供重新认证路径；
   普通服务故障不能被误报为“密码错误”或“尚未登录”。
6. **Given** 企业认证已成功，**When** 检查织境准入角色，**Then** 管理员或 AI 工程师可进入；
   仅有业务用户角色或没有准入角色时显示无权限，不进入登录重试循环。用户兼有多角色时，只要包含任一准入角色即可进入。

7. **Given** 退出织境后企业 SSO 仍有效，**When** 主动再次点击登录，**Then** 仍显示企业重新认证页面；本地错误密码不能进入，正确认证后回到安全站内目标。已登录时正常刷新和续期不重复要求认证。

### User Story 2 - 切换工作模块并调整页面空间 (Priority: P1)

作为数据处理与治理人员，我希望通过统一导航找到首页、资产搜索和 Agent 工作台，始终知道自己在哪个页面，
并能收起二级菜单扩大工作区域；刷新或返回时仍能回到正确位置。
尚未交付页面的说明只是分期状态要求，不是一个单独的用户目标。

**Why this priority**: 外壳的核心价值是稳定的信息架构；业务功能可以随后逐项加入，而不反复改导航方式。

**Independent Test**: 在四个一级入口和首页二级菜单间切换，收起 / 展开二级菜单，刷新及前进 / 后退，检查标题、选中态和状态说明。

**Acceptance Scenarios**:

1. **Given** 已登录，**When** 查看一级导航，**Then** 从上到下为“新建对话”“首页”“资产搜索”“Agent 工作台”；
   显示织境品牌，图标有可读名称，鼠标悬停和键盘聚焦时均可获取入口名称。
2. **Given** 位于首页，**When** 切换“概览”“审批中心”，**Then** 二级选中项、页面标题与正文一致；
   概览显示真实账号及建设状态，审批中心显示“审批中心尚未开放”，无伪造待办数量。
3. **Given** 位于资产搜索或 Agent 工作台，**When** 进入该页面，**Then** 分别显示“资产搜索尚未开放”
   或“Agent 工作台尚未开放”，并提供返回首页的操作。
4. **Given** 点击“新建对话”，**When** 进入目标，**Then** 显示“新建对话尚未开放”；
   归属 Agent 模块但与工作台页面标题明确区分，不创建空会话或调用执行服务。
5. **Given** 首页二级菜单展开，**When** 收起，**Then** 正文获得空间且仍有可发现的展开按钮；
   展开后当前二级选中项不变。在同次页面使用期间保持收起偏好，页面刷新后默认展开。
6. **Given** 当前模块没有已交付的二级内容，**When** 查看资产搜索、工作台或新建对话页面，**Then** 不显示假目录树或上游侧栏；
   首页概览和审批中心可返回时恢复首页二级导航，一级栏始终可用。
7. **Given** 已进入一个可访问页面，**When** 刷新、直接打开其地址或使用前进 / 后退，**Then** 恢复相同页面与导航选中态；
   未知地址显示“页面不存在”和返回首页入口，不落到空白页。

### Edge Cases

- 登录服务不可达、登录取消或回调失败：显示可理解的失败状态与重新进入路径，不泄露令牌或错误堆栈。
  取消或回调失败由现有登录入口带回织境的公共登录失败页；该页不依赖有效登录、只展示安全分类与重新登录操作，
  不继续使用失败的授权码。浏览器已跳到不可达的企业登录站点时，不能承诺织境接管浏览器网络错误；返回织境后可重新登录。
- 查询当前身份时服务暂时不可用：显示错误与重试，不直接当作会话过期反复跳登录。
- 用户显示名为空、姓名或账号很长：使用身份回退并限制溢出，账号操作仍可用，完整身份可读取。
- 不安全的登录返回地址：不得跳转站外；未知站内地址由不存在页面处理。
- 多次点击导航、收起按钮或重试：页面、选中态与可用操作保持一致，不叠加多个菜单或重复动作。
- 页面刷新或后退时失去会话：先重新认证，不能只恢复导航便继续展示前一用户内容。
- 已认证但仅有业务用户角色或没有准入角色：显示无权限并允许退出，不反复登录；管理员 / AI 工程师与其他角色并存时准入。
- Paperclip 的登录与退出不属于 004：织境不读取或联动其登录状态，织境退出以自身会话失效为准。
- 退出请求失败：不能显示“已退出”并假装成功，显示重试；本地删除失败返回错误，响应丢失可再次幂等退出确认。
  不调用 IdP logout，因此不再沿用 001 的上游退出处理；企业 SSO 是否仍有效不作为织境退出成败的条件。
- 窗口高度不足、长文案或页面内容很长：主内容可滚动，一级入口和账号操作仍可到达，不被浮层遮挡。
- 不属于 004 的原型控件：搜索与“问 Agent”隐藏或明确禁用并说明所属后续特性；禁用控件不能触发预设成功结果。
- 保留 001 的设备示例页作回归入口，但不放入正式产品导航、不作为登录后的默认首页；在本次 Web 准入角色规则下，其读取链路和已准入用户的示例行为不得因外壳改造失效。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 复用现有企业登录、平台会话与退出能力；未认证不能进入已登录外壳，不新增产品密码输入页。完成认证后仍须具备管理员（admin）或 AI 工程师（ai-engineer）任一角色，
  仅有业务用户（business-user）角色或没有准入角色时显示无权限，不因缺少角色而重复跳转登录。（US1）
- **FR-002**: MUST 从真实身份显示账号，默认进入首页概览，安全恢复合法站内登录目标；显示名按姓名 → 用户名 → 用户 ID 回退；v1 线上显示名称保持字符串保证。（US1）
- **FR-003**: MUST 区分会话失效、服务故障与权限不足，分别提供重新认证、重试或返回路径。（US1、D1）
- **FR-004**: MUST 正确结束平台会话并清理已登录展示；退出失败不伪报成功；刷新、后退与直达地址不能绕过会话校验。退出仅针对织境会话，不联动 Paperclip，
  MUST NOT 调用 IdP logout 或结束企业 SSO，不将其他客户端是否登录作为退出成功的条件。成功后停留匿名入口，不自动重新发起 SSO；
  用户主动再次登录必须重新认证成功后才能建立新的织境会话；BFF 固定使用 prompt=login，不能凭已有 SSO 直接进入。（US1）
- **FR-005**: MUST 按原型顺序提供“新建对话、首页、资产搜索、Agent 工作台”四个一级入口及织境品牌，
  具有准确名称、当前模块选中态与悬停 / 聚焦提示。（US2）
- **FR-006**: MUST 在首页提供“概览、审批中心”二级入口；二级菜单可收起与展开，同次使用保持状态，刷新默认展开。（US2）
- **FR-007**: MUST 根据模块显示二级菜单，工作台 / 新建对话不叠加占位的上游侧栏；
  资产搜索在 006 交付前不呈现假资产目录。标题、一级与二级选中态必须一致。（US2）
- **FR-008**: MUST 支持站内直达、刷新、前进与后退；未知地址给出不存在状态及首页入口。（US2）
- **FR-009**: MUST 为搜索、工作台、新建对话和审批提供明确的未交付页面，提供用户能理解的说明及返回首页操作，产品界面不显示 spec 编号或开发排期，
  不以假会话、假数据或假任务代替。（US2）
- **FR-010**: MUST 提供首页问候，并按原型保留概览指标、最近资产和我的待办的布局区域；
  尚未有真实来源的区域显示未交付 / 待接入，不显示虚构数值，不把缺失数据解释为零。（US2、D1）
- **FR-011**: MUST 将顶部搜索和页面“问 Agent”等原型入口标为未交付并禁用，或暂时隐藏；界面不显示开发编号。
  不建立搜索接口、Agent 会话、审批提交或执行沙箱连接。（US2、D1）
- **FR-012**: MUST 提供统一亮色视觉规则，覆盖品牌、文字层级、颜色、间距、按钮、面板、状态标签及输入控件；
  后续页面能够按同一规则接入，暗色主题本期不交付。（D1）
- **FR-013**: MUST 提供可复用的加载、空内容、错误、无权限、未交付状态组件，分别定义文案、动作和可用性；
  开发示例可独立呈现全部状态，普通用户导航不暴露示例工具。（D1）
- **FR-014**: MUST 在 1280×720 与 1440×900 桌面窗口、100% 缩放下支持四个一级入口、二级收起 / 展开和账号操作，
  无页面整体横向溢出或遮挡；长内容允许在内容区滚动。移动端专项适配不在本期。（US2、D1）
- **FR-015**: MUST 支持导航、账号、收起 / 展开、返回和重试的键盘操作，焦点可见且有可读名称；
  状态不能只以颜色区分，中文长文案不能覆盖操作区域。（US2、D1）
- **FR-016**: MUST 以简体中文呈现织境自有文案，采用统一文案入口以便后续扩展语言；不要求本期交付英文或改造上游文案。（D1）
- **FR-017**: MUST 延续既有服务端鉴权边界与会话安全要求，浏览器不持有身份令牌或服务凭证，不直连底层业务服务；
  企业登录跳转不受此业务访问限制。Web 准入角色 MUST 由服务端按已验证身份检查；受保护的 Web 业务接口沿用相同准入边界，
  无准入角色不能通过直接调用绕过页面限制。允许用户获得必要的拒绝状态并退出会话。
  不得以隐藏按钮替代服务端校验，不新增数据层授权或多租户能力。（US1）
- **FR-018**: MUST 提供开发验收用公共组件 / 状态示例，以及新页面接入统一外壳的简短说明；
  不交付 Agent 表格、子图、对象卡片、口径差异四类业务结果组件。（D2）
- **FR-019**: MUST 完成提前嵌入兼容性调查并交付可复现报告，覆盖 D2 的四个主题，
  明确验证版本、步骤、证据、未验证项与 007 的后续工作；技术选择与具体方案在 plan / research 中确定，
  不复制上游 UI、不将试验当作正式嵌入交付。（D2）

### D1. 设计系统与公共组件交付

这部分是 004 的公共交付，不单独包装为用户故事；它支撑 US1、US2 及后续页面。
基于 HTML 原型提炼亮色视觉规则，范围只覆盖外壳需要的基础组件。

| 交付物 | 本期范围 | 验收方式 |
| --- | --- | --- |
| 亮色视觉规则 | 品牌、主色 / 中性色 / 状态色、文字层级、间距、圆角、边框与焦点表现 | 在组件示例及两个外壳页面中比较，相同语义的样式一致 |
| 布局与导航 | 一级栏、可收起二级菜单、页头、内容区、账号入口 | 依 US2 逐项操作；桌面尺寸与键盘要求见 FR-014、FR-015 |
| 基础组件 | 主 / 次按钮、文本输入、面板、状态标签；包含需要的禁用、聚焦及加载状态 | 开发示例中逐项展示，按钮可按说明操作；不接入业务接口 |
| 公共页面状态 | 加载、空内容、错误、无权限、尚未开放；页面不存在沿用相同提示规则 | 开发示例逐项触发并检查文案、可用动作、结束与恢复行为 |
| 文案 | 简体中文统一管理，页面使用用户语言 | 产品界面不出现 spec 编号、后续开发特性号或技术 spike 提示 |

公共状态的具体要求：

1. 加载过程中相关操作不可重复提交；成功或失败后结束加载，不无限转圈。
2. 空内容说明当前没有内容及可执行的下一步；不得与“尚未开放”混用。
3. 错误提供重试或返回路径，不暴露凭证和堆栈；重试成功后恢复正常展示。
4. 无权限不显示受保护内容，允许返回可访问页面；不得暗示简单重试即可获得权限。
5. 尚未开放使用“资产搜索尚未开放”等文案和返回首页操作，不假造资产、会话、待办或操作成功。
6. 状态有文字说明，不能只靠颜色表达；焦点、键盘及长文案要求与其他外壳组件一致。
7. 首页问候使用真实账号；无真实数据的区域显示“尚未接入”或“尚未开放”，不填零、不显示模拟统计为真实指标。

组件与状态示例仅由开发侧验证并提供证据，不纳入用户手动验收步骤，也不加入普通用户的业务导航；不要求建设新的组件管理平台。
表格、子图、对象卡片、口径差异等 Agent 业务结果组件由 007 交付。

### Key Entities *(include if feature involves data)*
